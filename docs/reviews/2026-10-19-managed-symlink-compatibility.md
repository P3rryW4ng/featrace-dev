# 仓库内受管符号链接：最小兼容方案评审

日期：2026-10-19。状态：用户已明确批准最小兼容修复；本地候选已实现，验证结果另存。尚未发布安装，不操作业务项目。方案形成时仅有文档授权的历史边界保留在整理前记录中。

## 问题与事实来源

CC 转交 OGFR-8024 只读核对：14 个 .claude/skills/<name> 都是相对链接，指向 ../../.agents/skills/<同名>；目录存在，46 个目标文件受 Git 管理且未忽略，没有更深链接。来源为 2026-06-11 的 85d97ac6b1。8 项门禁、构建脚本及钩子不直接引用这些链接，但 Claude 技能发现、skills-lock.json、项目 comet 规则会使用它们。这些是转交事实，维护侧尚未直接读取业务仓验证，不把它们当独立复测证据。

维护侧已核对当前 main / 0.18.0 Python：check_identity.collect 拒绝 Git mode 120000；regression_continuity.check_worktree 拒绝任意路径组件为符号链接。现有测试明确要求拒绝链接。这是已知输入类型未支持的兼容边界，不是门禁命令执行失败，也不是业务缺陷。0.18.0 升级不能直接解阻；0.15.1 曾执行成功不代表保护等价。

## 建议最小范围

仅支持本例所需的“已提交、仓库内、相对、直接指向受管目录”的链接。继续绑定整个既有输入范围，不排除 .claude、.agents，也不以“Gradle 不读取”认定它们无关：AI 工具链本身会读取这些说明。

1. 链接必须在 HEAD/索引有明确的 120000 身份；记录并比较 readlink 得到的目标字节、Git blob、实际文件类型。不能只 resolve 后哈希目标，从而遗漏链接换向。
2. 允许前导 ../../ 这样的相对段，但从链接父目录解析后必须留在仓库根内；中间出现 .. 或 . 的复杂路径首批仍拒绝；拒绝绝对目标、越界、.git、.agent-workflow 内部控制数据及跨子模块目标。不能按目标字符串含 .. 一律拒绝本例。
3. 首批只支持直接目录目标；目录本身及路径组件不再含链接，目标存在且不是仓库根。目录里的实际成员应与受管目标范围核对，文件按原有字节/权限规则采集。链接链、嵌套链接、循环、悬空和未受管目标明确 unsupported，不自动遍历它们。以后若有真实需求再扩展。
4. 目标文件变化、增删、改权限、目标换向或链接变普通文件都须进入差异；不得因目标已扫描而遗漏链接身份。两个链接共用目标可去重读取，但不省略各链接的映射。
5. 捕获前后核对链接和目录成员身份；路径换向、读取失败或成员漂移一律 unknown。设备延续仍要求实际受管内容等于当前 Git 树，assume-unchanged / skip-worktree 不能隐藏变化。避免在可替换链接上盲目跟随打开文件。
6. 不改变 workflow 记录、锁、安装目标及证据文件的既有禁止链接约束。本批不是“所有路径允许符号链接”，不支持外部依赖目录。

## 实现落点与兼容约束

复用一个输入解析/身份核对实现，供 check_identity 与 regression_continuity 调用，避免两套接受条件。同步检查 project.py 的质量快照/比较、legacy 门禁、check_runs、新人工 scope 以及所有最终状态/审计读者；普通 evidence_carry 的历史 Git tree 路径不能被误当成已经验证实际目标。

优先保持普通文件的既有身份和业务记录格式；链接身份若引入新结构，须显式区分版本或能力范围，不能塞进旧格式让旧读者静默忽略。具体身份格式、旧读者拒绝、安装文件清单及版本选择在开发前确定。不得为本例自动启用 execution_contract2、迁移人工 schema5 或清除 unavailable 历史。旧安装回退与新身份数据读取分别验证。

## 验收矩阵候选

| 类别 | 输入/动作 | 预期 |
|---|---|---|
| 正向 | 14 个相同形态的链接、46 个受管文件，含合法 ../../ | 自动身份可识别；设备捕获可进入正常审查资格；不自动判 supported |
| 保持保护 | 无链接普通仓、workflow-only 提交、已登记外部必要输入、子模块 | 普通结果不退化；原不支持类型继续明确拒绝 |
| 内容变化 | 链接目标文本换向、目标文件字节/权限变化、增删文件、目标文件标记 assume-unchanged | 检查结果过期或未知；设备干净输入核对拒绝，不能延续旧绿灯 |
| 非支持 | 外部/绝对/悬空/循环/嵌套链接、未受管/被忽略成员、内部控制目录目标 | 明确 unknown/unsupported，无越界读取，无自动排除 |
| 漂移 | 双次采集期间换链接、目标替换或成员变化 | 拒绝捕获/采用；不产生可认证成功 |
| 读者 | legacy 与新检查、设备延续、人工 scope、状态/最终审计，旧读者 | 当前读者一致；旧读者不能把新身份误当完整旧身份 |
| 生命周期 | 执行前 unknown、正式执行成功/失败/中断、后续输入变化 | 保留旧拒绝和失败；只用实际新执行更新当前结果，不将 unavailable 改写成新通过 |

先做合成正反例及完整仓库回归，再验证精确发布候选/安装和读者兼容。最后让 CC 在原项目新执行正式门禁及延续流程，才证明真实解阻。不能只把那条 raise 移除后用一个成功夹具宣布完成。
