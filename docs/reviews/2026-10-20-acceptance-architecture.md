日期：2026-10-20。评审基线 main `3f5ddcee232bea98ed09f8dab5e3f9ac2837658e`，正式运行0.18.4/113。授权仅为架构评审与维护原则记录；不开发新合同、不改安装、不重验已结项需求。本报告的替代方向是建议，未获实现授权。北极星和当前开发者辅助定位保持不变。

## 结论及证据强度

审查者也是此前0.18.3/0.18.4的实现维护者，本评审不是独立审查或第三方认证。通过列举反证、竞争方案与未知降低自我辩护风险，但仍可能有遗漏；正式替代设计获批前应接受产品所有者质询，必要的独立复核须另行明确范围和成本。

推荐分层重构适用性/失效与复核绑定，保留原始事实、来源权威、输入身份、失败/未知和完整交付覆盖。不是全盘重写，也不是继续无限追加例外。已有源码与反复案例足以立项评审，不要求再承受一次耗时案例才承认结构问题；候选是否更安全/更便宜仍待相同输入对照，不能预先宣称。

“科学”指依据可追溯、推理可反驳、保护与代价明确、反例和未知公开，不是绝对正确保证或使用某种架构名称。现有设计并非毫无依据：最初采用保守整体绑定来防止未登记影响、需求扩大、旧包及历史成功掩盖失败。其保守性不等于长期成本合理；增加更多摘要也不等于语义更可靠。

当前已区分历史事实和现时适用性，历史通常仍保留；不能误说现系统会删除旧观察或把stale定义成业务失败。缺陷在于多个层的当前性依赖同一批广泛输入，导致本可独立判断的事项一起过期，并反复付出重新登记/解释/审查成本。

## 三个竞争方案

A：维持全局合同并继续提示/批次补丁。迁移成本最低、保护熟悉、已可处理部分案例；不能改变广泛失效与多协议选择的结构成本。适合短期兼容，不建议再作为唯一主线。

B：保留证据内核，重构主张适用性、检查事实组合与终审绑定（推荐进入详细设计）。可复用attempt、来源索引、历史原件、文件身份与负向保护；显式切断“说明改动→所有执行重来”的传播。主要风险是依赖/权威遗漏与旧读者误读，必须通过全局变化检测、未知保守、跨读者反例与显式迁移约束保护。收益未测，不能预先保证一定优于安全定向重测。

C：从头重写验收内核并一次性迁移。可统一模型，但回归、迁移和丢失边界知识风险最高；目前没有证据证明现有事实/身份内核不可复用。若B的技术设计证明旧写入/读者无法隔离，或新旧共存成本不可控，才升级为C；不因“不喜欢补丁”直接重写。

不使用主观评分冒充量化比较，不因0.18.3/0.18.4已经开发而默认保留。它们有接续/兼容价值，但未证明净收益；本应在广泛耦合已有证据时先做本评审，前期“合成可采用”不足以论证全部架构合理。后续如B取代其诊断来源，相关提示逻辑应同步收敛，不能永久叠加。

## 候选模型与待解决问题

建议四类职责分清，可通过改现有规范记录实现，不预定另造四份台账：

1. 执行/观察事实：做过什么、真实输入/环境/包、结果、产物及原时间；不可变。环境未绑定则证明范围受限。
2. 主张版本：需要证明什么，精确来源、用户决定、前提/例外/否定和共用约束；独立版本而非随意改文本保留旧通过。
3. 适用性/覆盖判断：哪些事实在当前条件下支持哪些主张；执行输入相等不代表断言充分，依赖列表不等于完整。
4. 交付组合：所有活动主张是否有当前充分支持或有效豁免，项目必需检查/回归、执行生命周期和授权是否满足；目录/数量/摘要齐全不是成功。

全局变更清单作为漏项检测而保留。未命中声明依赖的变化不能自动无影响；需确定全局约束、构建、主题/资源、调用方和环境边界，未知则扩大调查或测试。相同代码不代表相同环境；旧观察有多次、互相矛盾或最新负向时，必须有明确选择与冲突处理规则，不能挑一个通过。

详细设计必须回答：一项检查的输入闭包怎样界定/审阅；公共构建与环境污染怎样传播；业务/审计说明字段怎么分开而不藏语义；AC拆分/合并和历史多观察如何引用；同一主张最新失败与新版本失败如何显式解决；条件来源是改字还是改权威如何判定；并发/半写入/读者不一致怎样拒绝。没有可靠办法就保守绑定或缩小首批范围，不用LLM保证完整图。

## 开发批次与旧路径退出（尚未批准实施）

0. 当前只完成评审和维护原则记录。下一步交付详细接口/合同、字段/读写者清单及迁移/退出设计，请产品所有者批准后才改运行代码。
1. 先在隔离数据中实现一类证据的主张级适用性与终审组合，优先解决已证实的共享语义失效；自动/设备事实复用既有原件，不顺带替换所有执行器。确定稳定identity/version与权威关联后才能动摘要。
2. 再按实测主瓶颈决定检查级复用或设备观察组合，不能仅凭潜在收益同时开两个内核。若共同输入始终无法安全细分，保留保守检查并如实报告收益不足。
3. 发布和启用分别评审。新合同按真实契约影响选版本，不能伪装普通提示补丁；参与读者明确最低版本，旧项目不静默迁移。
4. 迁移只读原事实并追加必要适配/当前判断，不改原测试版本、时间或旧审核结论。旧合同与新合同不得同时写同一活动需求；试运行仅在隔离副本对照，不让真实项目双重记账。
5. 接管后停用被替代的新写入入口与重复状态，保留历史只读适配；全部读者改读同一适用性结果。列出具体删除文件/分支和完成条件，不能只加新reader让旧writer永久存在。必要的合法遗留项目可留有版本边界的支持策略，不保证无限期双栈。
6. 回退：启用前可恢复备份；启用后旧工具不能正确读取新记录时必须拒绝，不能删新事件降级或自动回旧通过。真实UI项目试点在候选正确性/迁移验证后开始，业务紧急工作可继续用0.18.4，不因工具评审阻塞交付。

## 公平对照与验收反例

同一合成仓库、原始产物、变更序列和交付主张运行旧方案及候选，先审查等价范围/环境。严格旧合同阻塞与候选有据支持分别记录，不改旧规则使其故意失败。不得用“行都绿了”或更少Agent数量代替质量对照。

| 变更/反例 | 预期保护 |
|---|---|
| 无关说明或记录进度变化 | 不重新执行；若分类不明则调查，不能按文件名无条件忽略 |
| 只改一个局部要求 | 该主张重判，其余判断需有输入/权威不变依据；不是整批自动保留 |
| 共享主题/字符串/导航或构建规则变更 | 传播到所有实际受影响主张，未知消费者不能免验 |
| 新/改断言或测试环境变化 | 不能用旧执行证明新断言；公共fixture影响不能漏 |
| 最新失败、部分执行、中断、缺终态、后台进程 | 相关当前交付阻断，不从更早成功或其他检查组偷绿 |
| 旧包、原件损坏、外部环境未核实 | 保留历史而不认证当前包/环境；不得重签旧时间 |
| 多次旧观察互补/矛盾 | 显式引用每次身份/条件并审核组合，矛盾必须解决，不只挑最后或最有利结果 |
| 新条款/豁免范围变化、来源歧义 | 不能推定新授权；明确产品决定与证据缺口 |
| 冻结后变更、并发写、跨需求错配 | 拒绝采用，保存失败/原件，无部分静默通过 |
| 较旧读者/混合合同 | 明确拒绝或有据适配，不无声回退旧成功 |

至少有局部UI、行为和共享影响三类输入；纯展示成功不足以证明机制安全。反例应实际破坏必要条件验证拒绝能力，不是只匹配提示字符串。无已确认错放行是发布前必要条件，不是有限样本证明零风险。

成本沿已有日志与可选stage-cost采集：物理命令/构建/安装、观察、登记、实际复核内容及重复、等待/人工介入、扫描路径/读取量、恢复和新机制自身成本。墙钟与人工劳动区分、并行不相加；令牌/缓存读写与实际可归属费用分开。业务样本不可与8025直接算节省百分比；缺可信基线就只报告本次观测。性能不预设固定提速比例，比较等价交付范围下总成本和误阻塞，并保留新方案更慢的结果。
