# GAP-05 扫描粒度隔离测量

日期：2026-09-22。环境：本机已安装 dev Skill 0.5.13、独立临时 Git 项目。夹具含 2024 个已跟踪文件、21 个 `package.json` 清单和 2002 个 Python 源文件；仅 `src/registered.py` 登记为基线证据。原始结果保存在本机 `/private/tmp/gap05-scan-measurement-20260922/measurement.json`，不会提交到仓库。

本次只测 `project.py` 的确定性指纹、prepare/publish、verify 和备份行为，没有运行 Claude Code 语义审阅，因此不能代表真实项目 `/dev scan` 的总时间。每个变化场景都从同一份已验证基线复制，避免前一场景污染后一场景。

| 场景 | verify | prepare + publish | 备份 | 结论 |
|---|---|---:|---:|---|
| 无变化，连续 3 次 | 每次 valid | 平均 0.117 秒 | 0 | 基线字节不变，明确返回 `BASELINE_UNCHANGED` |
| 未提交、未登记 README 改动 | valid | 0.116 秒 | 0 | 指纹不读取该文件，变化未进入基线判断 |
| 已提交、未登记 README 改动 | stale | 0.119 秒 | 1 | 仅 Git HEAD 改变也触发全局过期和完整基线备份 |
| 未提交、已登记源码改动 | stale | 0.117 秒 | 1 | 登记证据哈希变化被正确捕获 |
| 未提交、未登记源码改动 | valid | 0.117 秒 | 0 | 即使 Git 显示已跟踪源码有修改，当前指纹仍会漏掉 |

读取范围实查为：遍历项目目录寻找固定名称的构建清单并读取本夹具 21 份清单，读取 Git HEAD，读取显式登记的 `src/registered.py`，并检查根 `AGENTS.md`/`CLAUDE.md` 是否存在。普通 README 和未登记源码内容不进入摘要。目录遍历仍经过源码目录，但不读取普通源码文件内容。

隔离结果同时确认两个既有判断：保留 Git HEAD 能发现已提交但未登记的源码变化，却会让已提交的无关文档造成粗粒度失效；只依赖当前证据哈希又会漏掉未提交、未登记的源码变化。直接删除 HEAD 检查会把第一类保护一并删除，不能作为修复。

下一步若实现最小改进，应先让 verify 区分“清单/规则/登记证据变化”和“仅 HEAD 变化”，在仅 HEAD 变化时列出提交间路径供 Agent 局部判断；同时检查工作树中 `.agent-workflow/**` 以外的已跟踪与未跟踪变化并明确警告未登记路径。无变化不重写、不备份的现有行为应保持。是否减少真实扫描时间仍需在真实项目测量 Agent 实际阅读范围和耗时后决定。
