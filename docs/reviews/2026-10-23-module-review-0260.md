# 0.26.0 模块顺序评审

日期：2026-10-23。对象：正式0.26.0及其后维护文档；运行来源91fc9a7。按用户批准顺序，只读核对源码、指引和既有验证，不派独立Agent、不运行新评分场景、不重测业务。本报告是维护者源码评审，不冒充独立安全审计或真实性能实验。

## 结论

没有发现足以支持再次整套重构的证据。合同3已解决主张/证明混同、单一最新事实覆盖、多余登记重跑及固定前驱桥接等此前问题；应保留这些保护。当前最需要补的是语义行为的真实验证，而不是再增加合同、永久文档或默认全量评审。

确认一项诊断可改进点、三处维护入口漂移；后三处本轮修正文档。诊断只列开发候选，运行代码未改。未知能力不判失败，也不据此宣布成熟。

## 1. 影响分析与测试选择

输入：请求、实际调用/资源/状态关系、项目规则。输出：组合分类、因果范围、逐标准证明要求和定向检查。

依据：task_workflow.py 的 validate_plan、selected_constraints、relevant_paths、criterion_stamp、check_identity_payload；task_inputs.py；task-workflow和Android指引。程序校验检查输入包含所声明标准的输入，局部未知隔离、执行身份与语义范围分开。实际调用关系由Agent调查，内核不自动生成完整依赖图，也不能判断一个填入的proof是否真的充分。

既有反例：test_evidence_core中的组合证明、静态结构主张、原生产者与时间、查询变化不重跑；test_task_extensions中的编译输入不扩大主张；test_review_boundaries中的局部规则变化。214项结果是程序保护，不是Agent测试选择准确率。

决策：保留。自然新需求中核查是否漏调用方、把展示误归逻辑或反向扩大测试；无需先开发一个“自动全仓语义分类器”。约束优先使用范围化对象，字符串代表明确全任务约束，不自动删除该表达能力。

## 2. 上下文恢复

输入：当前任务/选定主张；输出：分页状态、原事实、支持选择、未解决失败和当前规则。detail/review-input没有自动运行检查；合同3事实与附件有界，现有新进程探针验证了只读恢复及输出边界。它不是自动上下文预算器，也不证明真实压缩后Agent会读齐必要内容。

确认可改进点：view捕获ready抛出的ValueError/OSError后只返回SCOPE_NOT_READY。范围漂移、SCOPE_UNKNOWN及实际规则问题会被合并；计划详情能帮助追查，但状态不足以直接区分原因。不是错误通过，因为仍阻塞；影响的是定位成本。

候选小修：保持阻塞语义，返回有限、脱敏的已知原因码及对应详情入口；未知异常仍返回通用码，不能回显源文件/权限错误正文。反例至少包括局部未知、规则变动、缺规则、输入变动、未知异常、不写文件/不执行命令。开发前定向确认现有诊断需求，不借此引入新状态机。

决策：保留恢复架构；诊断候选列入下一批。自然压缩恢复待观察，不为当前评审制造假压缩。

## 3. 独立评审

依据：review_required、assess、view和review_input；test_review_boundaries及test_evidence_core的选定事实评审反例。评审作用于所选标准和事实，而非默认全部PRD；相关依据变化才要求重新判断。共享改动要求独立评审，但工具不自动识别哪个标准共享或高风险。

出处文件校验task、criterion、摘要、所选事实和fresh_context等字段；字段符合不证明独立上下文真的存在，宿主必须提供真实出处。内核不能替代语义评审，也不是防恶意同权限篡改的安全边界。

决策：保留，不恢复双重全量深入复核。下一次自然共享/高风险场景核对真实派发范围、输入完整性和重复读取；不要求每个私有UI任务额外派评审者来“测功能”。

## 4. 项目约束与授权

依据：task_policy.prepare/effective、check_policy、project-compatibility；已有范围/环境授权、规则变化和自定义忽略块拒绝用例。一份实际策略保留来源、权威、操作及环境；执行前检查相关规则，同范围授权复用，不与宿主/hooks竞争。

边界：内核执行器校验其运行命令的声明操作；Agent直接提交、设备工具或连接器行为仍依赖实际宿主规则和Agent遵守指引，策略文件不是通用权限沙箱。空规则不是已证明“没有规则”，也不能代替初次实际调查。

决策：保留；未发现需要另造项目约束覆盖层的依据。后续核对不必要询问与实际越权，不能用减少询问数量替代权限正确性。
