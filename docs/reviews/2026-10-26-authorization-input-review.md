## 一、授权与事实身份

### 当前机制与实际问题

task_policy.effective（153–164）按路径/操作/环境选规则，核对来源摘要，enforce时ask/denied硬拒绝；这是必要的权限保护。run_check（468–480）在判断缓存复用前先执行权限检查。没有一次性或任务范围例外授权入口，实际批准只能被转换成长期规则的permission/authority/decision变化。

check_identity_payload（407–420）、criterion_stamp（430–434）和analysis（324–331）都包含适用策略内容。因此“临时allowed后恢复ask”同时改变执行摘要、标准摘要和结项上下文。P1实际只执行一次，恢复ask后CHECK与CLAIM阻塞；再次请求原结果也被ASK拒绝。原事实保留未被删除；恢复原allowed又能复用原ID。这证明的是**当前授权状态与历史事实适用性耦合**，不是成功执行从未发生或工具强制已经重跑。

源码支持的规则还包括产品约束/必要门禁和来源变化；不能把整个policy一律从摘要中删掉。现有测试中“规则改变需重新考虑、拒绝阻止执行、仅适用范围受影响”应保留。

### 取舍

| 方案 | 判断 |
|---|---|
| 保持临时改长期策略再改回 | 拒绝作为日常授权机制；容易误扩大权限，并造成无关适用性变化 |
| 直接忽略policy或ask | 拒绝；会失去来源、拒绝和真实项目规则保护 |
| 为每次执行另问一遍、另建永久审批台账 | 拒绝；既有同范围授权不应重复收集，增加流程成本 |
| **分开执行条件、当前许可与原执行授权依据** | 推荐局部替换；保留执行器、范围、事实和拒绝边界 |

### 推荐合同

1. 长期策略仍表示项目的默认选择，不因一次“可以编译”永久变成allowed。当前许可在实际启动新进程前判断；正常查询原事实不是新执行。缓存复用应明确标复用，不能表述成再次执行。
2. 实际批准按其原意引用：明确一次仅覆盖一次尝试；已明确覆盖本任务相同范围的构建/修复重试则在该范围复用，不再逐次询问。不能把一次批准擅自升级为整个项目、生产或push授权。
3. 例外限定任务/检查、命令、作用路径、操作与环境，保存真实来源/权威/时点和适用边界；一次性授权原子占用，失败或中断仍是一项实际尝试。只读规划和执行前拒绝不冒充已执行。状态有界，保留当前使用/必要失败引用，不建永久审批史。
4. 普通ask可由适用的真实批准满足；denied、已变化的来源、宿主/CI/hooks限制不能被一个通用“同意”字段绕过。真实产品所有者修改项目约束需显式协调，不由执行授权默改规则。
5. 原命令记录保留当时授权依据。到期/用完或恢复ask只阻止下一次未授权物理执行，不自动否定当时合法执行的事实。原执行不合法或授权被纠正时须保留问题并按真实决定处置，不能借分离洗白。
6. 内容/工具链/环境/产物、实质要求及有效期继续决定证据适用性。仅授权开关与纯批准文字不混入内容身份；实际测试要求、规则内容或产品承诺变化仍需定向重新判断，不能统统排除。

读写范围：policy准备/查询、run物理执行与复用分支、执行记录/协议、analysis/criterion stamp、status/assess/close、correct/prune/cleanup及指引。淘汰把单次批准写成长期allowed的路径；不保留第二套可任意绕过的执行器。

## 二、验证资料与临时脚本

### 现有能力、缺口和反证

P2确认，外部CSV与脚本使用已有checks.external_inputs即可进入摘要：脚本改动重新执行，CSV改动触发实际失败。它不是只能用于JDK，也不是所有外部资料都无法绑定。CC该部分归因过宽。

但attach（518–547）经safe只接受仓库内相对普通文件，标准sources也受同一路径约束；外部附件/标准来源均拒绝。valid_inputs（208–213）对.featrace一律拒绝，与“任务临时工作写入.featrace”指引冲突：合法临时验证脚本、参照资料和可变控制/输出未区分角色。

P3确认，若只把该脚本路径写进argv、未纳入任何输入，改脚本后仍复用旧成功。argv字符串不等于脚本字节；内核不推断全部动态读取关系，计划声明不足也有Agent责任。不能把这条记录算作可信的当前验证来源。

P4进一步确认，同一个控制区域文件改用绝对external_inputs会被接受并检测字节变化。这不是未检测字节的漏洞，但说明**路径写法与输入角色的限制不一致**。不推荐用绝对路径绕过，亦不接受“全放开.featrace”作为修复。

### 推荐局部替换

保留现有外部输入收集器、哈希、大小/数量/符号链接/移动中变更保护。统一解决“代码路径、执行输入、产品来源、证据副本和控制输出”的角色，选定资源能被各读者一致引用，不仅在某入口例外放行。

- 仓库业务路径继续用现有精确路径。真实外部实时执行输入继续使用external_inputs，不复制整个外部目录。
- 允许显式选定的外部文件或本任务临时脚本/资料，作为**任务输入快照**登记：复用现有有界附件目录与UUID所有权，扩展明确的输入角色、内容身份及必要原来源信息，不建全局对象库或第二永久档案。原文件保持只读、不归清理器所有。
- 检查/标准引用该输入ID，指纹含实际所用副本的字节身份；执行命令的脚本路径与所选输入必须一致，不能只记录argv或借助未声明脚本。读者核对角色、所属任务、完整性、数量/大小及当前可用性。仍不承诺自动发现所有Python导入、Shell读取和动态网络依赖。
- 临时验证工具是检查输入，不因它参与执行就变成业务影响scope。参照CSV可同时是来源及检查输入；内核明确“来自提供的CSV”，不提升为“核对过iOS源码”。
- 快照仅证明所捕获版本；原外部资料后来改变不等于副本变了，不得自动宣称远端当前一致。需当前外部状态的检查用实时外部身份/查询及原时点，保留未知。
- 原始任务JSON、策略状态、锁、当前日志/观察输出不能因更换路径写法变成自己的输入。普通相对路径与external_inputs在实际解析后使用相同角色边界；合法已登记输入与控制数据分开，避免递归和自我盖戳。
- prune保护活动检查、标准、评估、更正及失败处置所引用的输入；到期只清理所拥有副本，不删外部原件。延期/未解决知识沿现有交接规则留最小摘要，不永久保留全部CSV/脚本/截图。

读写范围：attach/资料登记、plan/argv解析、输入收集/规则匹配、sources/证据引用、执行/观察/判定、详情与生命周期。优先复用已有附件注册和外部收集能力，删除“生成目录一刀切＋外部拼写例外”的互相矛盾边界；不能增加另一路不校验的来源。

## 三、影响分析指引

本次无需分类引擎、强制第二Agent或每需求新增表单。拟补一条条件式调查：改显示值或数据表时，追踪同一值是否参与搜索/筛选/排序、选择身份、回显或接口映射；展示名称与稳定标识分开。存在真实交互影响时扩展相关标准和定向检查；无路径则不重验逻辑。

原授权只改显示时，优先保持原交互含义；若实现方案会改变用户可搜索名称等产品结果，先说明并使用真实决定。已有明确原要求可直接执行，不把所有文案改动都升级为选择题。现场观察到图标/文字正确可以记视觉事实，但不能同时把尚未获准的搜索变化判为产品符合。

静态已充分证明国家码提交不变时，不自动要求真实Next请求；共享可选标题默认值与旧调用核查充分时，不自动深审全部调用业务。新交互风险不是无限回归的理由。

| 组 | 必须验证的正反例 |
|---|---|
| 授权 | 无批准ask不启动；适用批准不改长期策略；到期/恢复ask能查用原合法事实但不能新执行；越范围/换环境/命令改变拒绝；当前deny和来源变动不绕过；实质规则与代码变化仍使相关证据失效；失败/中断按实际授权边界处理 |
| 资料 | 外部CSV和临时脚本可明确引用；实际所用脚本/数据变化仅影响相应检查；原件变化与固定副本变化分开；未声明执行脚本不冒充可信输入；原始控制记录不能借绝对/别名路径进入；外部原件不删；篡改/丢失/超限拒绝；prune和清理不丢活动/失败引用 |
| 选测 | 私有静态标签仅验相关显示；标签参与搜索则补搜索；共享标题默认调用不重验业务；代码静态足够的无影响主张不强跑；搜索未确认不记产品通过 |
| 联合 | 授权、资料和产品决定分开变化，分别影响应当受影响的部分；旧负面结果、来源时点和对象不被重签；旧读者安全拒读；状态查询和文档整理不启动测试 |
