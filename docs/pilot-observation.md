# 真实试点观察标准（精简）

2026-10-23。维护侧观察标准，不是业务新增门禁或安装运行合同。适用于下一项自然需求；不重开旧需求，不为满足本表增加测试、压缩、设备操作或独立Agent。

## 开始时

复用正常需求沟通和任务计划，确认原始目标、实际影响、适用规则/授权及交付边界。记录实际安装/加载的版本和必要来源，不能只凭磁盘文件推断会话已加载。按当时资料确定必须证明什么、哪些检查或项目门禁必要，先固定判断边界；发现真实新影响时可有据调整，不事后改标准掩盖失败。

## 结束后一次只读核对

| 观察点 | 达标表现 | 需报告的问题 |
|---|---|---|
| 影响与测试 | 实际差异、调用方与所选断言相符；每项执行有风险或项目规则依据 | 漏验；UI标签掩盖交互；无因果的业务全量复测 |
| 新说明处理（发生时） | 明确改变哪些承诺/实现/检查；原事实身份不重签 | 改文字就重跑未变命令；偷偷缩小承诺或绕过失败 |
| 执行与证据 | 命令、实际测试和原产物生产者区分；适用结果合法复用 | UP-TO-DATE冒充新测试；重复执行只为登记；来源错配 |
| 连续工作与接续 | 同范围授权复用；若真实换上下文，能恢复目标、决定、事实、阻塞和下一步 | 重问已有决定；遗漏失败/限制；没有发生压缩却声称恢复通过 |
| 交付与知识交接 | 承诺有充分依据；必要原因/边界已有长期位置，或确认无需新增 | 编译代替业务证明；重要约束只留在将清理的临时文件 |
| 成本与介入 | 从现有日志统计执行/复用/返工及必要和非必要介入 | 凑测试次数；额外深审打分；无等质基线却宣称节省 |

各点只判“有证据支持 / 有具体问题 / 未知 / 未触发”，附原事实位置。未触发不是通过或失败。争议先核对产品权威、实际断言和因果路径，不能仅凭评估者偏好要求更多运行证据。范围内有真实缺口时正常修复/补证；不为工具评测补跑无关功能。

## 最少返回内容

在原会话一次简短回复即可，不在业务项目新增永久评分档案：

1. 版本/实际加载依据、工作项、原始目标及交付范围。
2. 实际改动和必要检查；执行/复用/重跑次数及重跑原因。
3. 哪些承诺来自运行观察、静态证明、原结果；原生产者/对象/时间可追溯。
4. 需求变化、接续、独立评审、生命周期是否自然触发；未触发明确写出。
5. 人工介入及原因、重要知识的现有位置、具体缺口/误阻塞/漏验和归因。
6. 可得成本、未测量项，以及下一项最小处理；无问题则结束。

时间只用执行计时或可靠时间戳，墙钟与人工投入分开；聊天/提交间隔不推断工时。执行、环境、记录维护、审阅、返工、人工等待/操作分别报告；无法分离就未知，不填0。并行时间不相加，token按原口径列出，不把缓存读取当账单。无同质量、同范围、可比环境基线时，仅报告本次观测，不算节省比例。

## 第二阶段的判读

错误结项、越权、隐藏真实失败、误删或泄露必须单列处置，不能被速度或平均分抵消。不必因一条尚待判明的维护问题自动重开业务结项，应区分业务证据缺口、工具误阻塞、指引/执行偏差和评估标准错误。

单次UI成功不能证明交互/共享改动准确，也不能证明复杂接续。利用后续自然出现的相关反例逐步补证；没有出现的能力保持未知。本表不另设每项全触发、固定样本数或固定耗时门槛，仍按ROADMAP的阶段出口判断，不以本表写完宣布阶段完成。相同事实不反复复盘；需要进一步处理时只针对具体问题。
