## 2. 单元A：替换存储表示，补齐证据所有权

建议新任务使用合同8，新存储格式明确版本。旧合同7继续用固定0.31.0，不自动迁移、重签或要求旧检查重跑。

## 3. 单元B：替换迟封存的当前源码依赖

- walk-start冻结当时标准及已声明文件/资产身份，保留目标、轮次和启动时间；只存相关有界身份，不复制仓库源码或APK。明确此身份不是动态依赖完整证明。
- 正常passed封存继续要求当前标准/输入匹配；不得用历史分支、改字或负面入口登记旧passed为当前passed。
- 新增显式历史负面入口，仅接收failed/unavailable。引用原轮次、冻结身份、原目标、真实采集时间依据和选定证据；登记时间与观察时间分开。不再读取当前源码伪造原source_inputs，也不要求临时回退代码。
- 实际观察早于修复但封存较晚时，可按原始日志/产物/现场记录作有范围的声明；不能单凭文件mtime证明设备采集时间。缺必要依据时保留“无法判定的发现”和缺口，使该轮仍需处置，不能自动转为可支持的运行事实或丢弃发现。
- 旧标准已变更/移除时仍保留原轮次发现，不强行映射成新标准通过。相关失败不得因不适用当前输入自动消失；转移范围须真实决定和交接，不能换ID隐藏。

## 4. 实施与验收顺序

1. 新合同/编码器纵切：纯合成往返、坏哈希/缺块/类型/超限/展开炸弹拒绝；所有入口只经统一读写；原子写入中断不损旧记录。
2. 执行身份：同合同内仅改编码不重跑；命令、环境、权限、实际输入或采集代码变更仍失效；旧合同不自动采用。紧凑编码和预算结果一致，拒绝后无进程/记录副作用。
3. 证据所有权与引用闭包：复制后源scratch删除仍可核查；复制失败/满32不留下虚假判定；原件哈希改变阻塞；更正、adopt和失败的间接引用保护，外部/未知文件不删。清理后的回执不宣称原件仍存在。
4. 历史负面纵切：改源码后保存原failed/unavailable；旧passed拒绝；原标准移除、缺采集依据、目标错误、条件不同不误配；负面始终需真实处置。并发、SIGKILL、预算不足及不同意图重试均保留输出。
5. 冻结后一次完整回归；按维护规则更新usage及日常流图、安装描述和使用指引。只有合成受控证据，不冒充自然收益。正式发布/推送/安装另按用户指示。

此方案无业务迁移。隔离新任务失败可保留并用固定候选工具查询/终止；恢复0.31.0只处理旧合同7，新合同8不可降号或改写为7。拒绝不兼容比静默误读优先。发布版本按完成范围评审，暂不写已发布版本号。
