# 受控执行环境与非交付终止：合同6候选方案

2026-10-27。状态：**产品所有者已批准合同6范围；受控环境开发中，非交付终止待实现，尚未发布**。现有合同5的CLI查询、压缩幂等性与有限诊断已分别验证，不能把其306项结果算作本方案通过。范围来自[底层评审](../reviews/2026-10-27-environment-lifecycle-review.md)。本方案不要求重开业务、迁移旧任务、永久保存历史或开发团队数据库。

## 目标与取舍

1. 让检查只因实际传入的环境与已声明工具链变化而失效，同时保留缺省的保守路径。
2. 让用户明确停止的任务可以“不交付地终止”，交接重要未解决问题后按既有策略清理，而不是假结项。
3. 继续一份有界任务、已有事实/附件/问题位置与清理器，不增加环境值档案、全局依赖图或永久任务历史库。

这是执行和生命周期语义变化，选择合同6，不把新字段偷偷写进合同5或保留两套可选写入者。旧1–5记录固定原工具，拒读不改文件，无自动转换。正式版本号只在实现/验证后按发布规则确定。

## A. 执行环境

### 配置和执行

检查新增可选execution_env。省略或mode=inherit保留当前行为：进程继承宿主环境，身份绑定当前默认变量集加env_keys；仍需调查额外依赖，不保证覆盖所有环境变量。

mode=controlled必须明确inherit_keys（最多64个合法、唯一变量名）和固定search_path（最多32个非空、无空路径项的已批准目录）。PATH不能同时出现在inherit_keys；不允许空路径项隐式搜索当前目录。不接受在任务JSON中保存任意秘密变量原值。

- 实际子进程env只包含选定且存在的宿主键，以及由search_path构造的PATH；未选键不能通过原env透传。选定键缺失就是缺失，不补造空值或默认批准。
- search_path是明确的执行配置，不等于工具二进制身份。实际使用的SDK/解释器/子工具继续采用已有exact/input_sets/external_inputs；不递归扫描全部系统目录，也不宣称自动发现动态工具。
- 顶层可执行文件必须按将要传入的PATH解析并绑定实际字节，启动使用该解析结果；不能按宿主PATH算摘要、再按另一份PATH启动。
- 在内存中构造一份启动环境快照，同一快照用于执行前身份和Popen(env=...)。事实只保留模式、允许键名/配置身份与摘要，不保存继承值。执行后按当前相同配置再核对输入；真正相关变化仍产生unavailable。
- controlled指环境变量控制，不是操作系统沙箱；运行时可能自行设置语言变量，网络/时钟/设备/动态读取也不因此变得可复用。remote/device/production原禁止内容缓存与期限要求保持。

身份绑定模式、实际传入环境、解析后的执行器、已声明文件/工具链和原策略/约束/协议。controlled不靠“认定不影响”来略掉仍传给子进程的变量。无选定模式时不自动升级，权限/deny/hooks不受影响。

### 替换范围与反例

复用task_inputs、task_execution和当前check_identity_payload，替换“全部检查都从宿主默认环境集合直接生成身份”的单一路径；保留inherit缺省。有限诊断仍是解释，不是缓存判据。readiness、授权定义、生产者、post-check、status/detail及指引共同调整，不加前驱哈希白名单。

必要反例：未选JAVA_HOME改变不影响受控纯检查且子进程不可见；选定变量改变必须失效；宿主PATH改变而固定search_path不变不应重跑；固定路径/实际工具字节改变必须失效；绝对解释器通过PATH调用子工具仍有真实输入保护；空/相对逃逸/冲突配置拒绝；inherit缺省、deny、过期与失败不降级。模拟常见POSIX工具链并记录运行环境；不宣称Windows/任意Shell/编译系统通用支持。

## B. 非交付终止

### 新操作与含义

新增retire ROOT ID --reason TEXT --authority SOURCE --decision-at OFFSET_TIME [--handoff EXISTING_ISSUE]，只针对明确选定的当前任务，复用真实已有同范围决定。不得因旧、满或清理失败自动代用户终止。

- 同一任务写锁内收集当前目标、已有事实、待决失败/未知、限制、原更正关系和代码变更边界；锁冲突返回busy，不终止在跑的检查进程。
- 适用于未完成任务，包括尚未结束的更正；已complete不改写原交付，只继续已有correct/cleanup路径。重试同一已终止任务为只读幂等，不改终止时间。
- 保存retired状态和独立退场回执：delivery_certified=false、真实retired_at、reason/authority/decision_at、未解决计数与必要交接身份。它不是complete、deferred supported或修复，不增加交付成功数，不解除原失败。
- correcting任务终止时必须保留原回执和未解决更正关系，不能把原错误更正标为complete。终止后禁止plan/run/observe/assess/authorize/failure等继续写入；查询仍能看到未解决事实与终止含义。
- 终止不自动回滚、删除或推送代码。若已有代码变更或材料风险，先明确其去留/交接；不把retire当“可以合并”。

### 长期知识与清理

存在真实失败、未解决更正、材料性限制/未知或未交接代码风险时，使用项目既有简短问题位置保存必要内容及原对象/条件/时点/证据身份，记录并校验摘要。只保存当前必须继续知道的事项，不永久复制日志或全部过程。无事实/变更/风险的空草稿不强制新建长期文档。

使用已有单任务256KiB、事实/附件和有限处置上限；一份退场回执不建立永久事件流。保留期从实际retired_at起算，不能用很早的decision_at制造“立即过期”。过期后复用cleanup/maintain，仍按回执确认的manual/compact/forget选择处理；缺失/变化的必要交接、未知文件、其他任务资料继续拒绝。原件和代码不删除。

status/list/storage单列retired，未解决计数仍可见，不能统计成supported或完成交付。compact/forget返回实际变化，沿用幂等性保护；全局累计没有被宣称自动有界。初版不提供静默原地复活：恢复是明确的新工作请求，调查当前代码和存活问题，不重签旧事实或恢复已删除证据，也不要求重读全部历史。

### 读写者与必要反例

load/save、mutable、begin/plan/run/observe/assess/authorize、correct/close、failure/defer、query/review-input、prune/cleanup/maintain、storage与接续指引要共同处理retired；旧读取器拒绝合同6。完成回执和退场回执类型不可混用。

反例：真实决定/明确任务范围缺失拒绝；忙锁不终止；原失败不消失；退场不算成功交付；未解决更正不被洗白；终止后写入口拒绝；重复退场不改时间；交接丢失/变化不能清理；未到期不能清理；仅删自有资料；恢复不回填/重签/绕过已知问题；旧任务和其他任务不动。

## 实施与验收顺序

1. 先冻结合同6形状、状态转换、读写者/错误码与实际权限边界，经确认后实现环境与生命周期两部分；不一次性扩展所有平台。
2. 每个完整小任务必要检查和隐私核对后本地提交；运行变化按仓库规则执行完整当前套件。受控子进程/交接清理用隔离项目，不借业务需求补测试。
3. 一次有限独立源码评审和最小原始任务前向演练，分别报告源码、程序、Agent与宿主边界。失败/拒绝/返工和新增记录成本原样保留。
4. 只有实际实现、反例与必要演练完成后才选择发布版本；推送和日常安装另授权。当前正式CC0.29.0不变，306项不冒充合同6验证。
