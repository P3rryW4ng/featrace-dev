# 影响分类、组合验证与项目约束裁决方案

日期：2026-10-20。状态：用户已确认方向并授权更新维护文档；**尚未批准本方案的运行开发、数据迁移、项目配置变更、发布或安装**。等待CC本次结项的已有记录后，核对具体缺陷与替换范围；不为复盘追加测试或复核。

## 目标与现有边界

适用于新开发、旧需求补充变更和Bug修复。先判断实际影响再选择检查与复核深度，不按需求归属、文件类型、行数或“UI”标签决定全量/免验。保留北极星：可靠、可追溯、受控且成本与风险相称。

0.19.0已提供schema6的统一判断、完整变化/主张核对及分组复用，不自动迁移旧项目；本方案决定应验证什么与审查多深，两者职责不同。不能把安装当合同启用。既有整组选中执行、设备/模块约束、不可拼接旧attempt等边界尚在；分类不创造不存在的复用路径。

## 1. 分类与组合

| 类别 | 进入条件 | 默认验证范围 |
|---|---|---|
| A 非运行内容 | 不改变运行、构建或正式验收语义的说明/注释 | 内容、链接及格式 |
| B 局部展示 | 单处文字/图标/颜色/字号/间距，行为不变 | 目标样式、换行截断遮挡、相邻布局及必要展示状态 |
| C 共享展示 | 多处使用的展示资源或组件改变，行为不变 | B加受影响用法，按不同布局/配置约束选择覆盖，不默认业务回归 |
| D 局部行为 | 校验、状态、局部数据/错误处理改变，依赖边界明确 | 定向行为、边界、错误路径与直接相关回归 |
| E 跨边界行为 | 共享行为、跨页面状态、接口契约、持久数据或执行链路改变 | 沿实际依赖扩展的集成/兼容及必要端到端验证，不等于全仓回归 |
| U 影响未知 | 需求、依赖、环境或产物身份无法确认 | 定向调查后分类；未解决必要缺口如实阻塞，不默认执行所有测试 |

按变更单元分类，一个需求可组合多类。最终检查为各单元检查的并集加相互作用检查，再去重；同一执行可引用多个目标。开发前初判，完成后按最终差异、调用/资源引用和共享关系确认；有据可升可降。修改金额单位或正式验收要求可能改变业务语义，不能因载体是字符串/文档就走B/A。

风险标签独立于类别：资金、安全、权限、隐私、多语言、字体缩放、无障碍、设备特异、兼容与迁移。标签基于实际影响，不因页面名称机械提升；只加强受影响范围的验证，不引入无依据矩阵。

每项检查须对应原始要求、批准决定、相关保留行为或具体风险；Agent推断须标明，不能静默扩大承诺。先判断已有结果适用性，再补缺口。定向诊断与最终门禁分开；满足目标、相关回归及既有控制后结束，不因内部阶段切换重复执行。

## 2. 复核范围

完整性核对覆盖全部当前交付主张；深入审查集中于变更/受影响项；有据不受影响项核对排除影响与判断复用依据，不重审原业务逻辑；未知项调查/补证。完整覆盖不等于全量深入审查。原失败、撤回、缺证与合法豁免单独处理，不能借改key、分类或换审查者凑绿。现有独立复核要求若要调整，维护侧明确修改并验证，Agent不得临时跳过。

## 3. 项目约束：扫描时识别裁决，后续统一执行

复用既有project-compatibility.md与基线draft/publish机制，不另建规则数据库或第二状态机。有效约束视图优先由baseline/conventions.md与coverage.md承担，原文件以引用为证据；具体存储/校验改动需另评审。

- 兼容规则：保留并注明适用范围。
- 重复流程：明确唯一归属，合并/替代重复登记与执行，不同时运行两个router。
- 实际冲突：集中列出精确来源、冲突内容、影响的Skill功能、取舍风险和建议，只对未决冲突请用户裁决。
- 来源不明/过时/范围不清：调查标明未知，不自动视为全局强制，也不自动忽略。
- 实际宿主权限、hook/CI强制：独立识别；摘要与选择文档不能解除限制。若须变更，明确权限和最小配置调整，不能绕过拒绝或影响协作者活动。

每条有效约束保留原始路径/章节、适用路径/环境/操作、遵循/合并/替代/不适用/待裁决结果、依据/授权范围、影响功能和未决限制。用户已有裁决不重复请批；只读取当前任务适用约束与必要原文。来源变化、路径/环境切换或新hook出现时局部重核；旧摘要不能覆盖新规则，也不因无关配置变化重扫/作废全部业务证据。

测试范围由实际影响、已裁决项目约束和适用风险保护共同决定。区分强制项、条件项、历史选择及脚本捆绑。合法适用的强制检查保留；不合理约束须由有权方协调实际规则/配置。仅改变Skill文案不能声称项目强制约束已解除。

## 4. 授权与自动执行

用户已明确授权在确认的test环境内自动执行任务所需测试，不逐项重复请批；特殊账号/邮箱/凭证或本人才能完成的操作再取必要输入。环境必须核实，不能将生产或外部操作以test名称混同。实际宿主权限限制与业务授权分开报告；本方案记录不启动任何测试，也不改权限配置。

开发自验负责本次要求与相关回归，不默认重复后续测试/产品验收的全部工作。真实覆盖缺口仍需补证，不能以有人后续验收为由省略。

## 6. 后续实现与验收候选

先核对普通入口、项目兼容/基线读者、门禁选择及终审实现，比较保留/修正/替换/删除。删除冲突旧指令或收窄错误强制，不能新分类后仍无条件运行旧全面验收。尽量复用既有记录，只增加类别、依据、范围、扩大条件所需信息，具体合同变更另行批准。

反例覆盖：局部展示不触发无关业务重验；共享展示选择不同受影响用法；混合改动组合去重并查交互；伪UI行为改变升级；U与最新失败不自动保留；约束重复只执行一次；强制冲突不能只靠摘要绕过；来源变化局部重核；压缩后恢复有效事实不重复执行。与0.19.0负向、锁、执行身份及完整交付控制保持兼容。

真实案例记录执行次数/原因、误阻塞、漏验/误结项、人工介入、证据与复核成本和实际捕获问题；同范围同质量比较。未知数据保留，不预设比例；分类及约束维护自身成本也计入。单例或合成通过不代表第二阶段完成。
