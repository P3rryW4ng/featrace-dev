# 0.10.1 设备验收准备隔离复核（2026-10-12）

本轮只测试 Verify 的分流说明，不连接真机、不改业务仓库，也不声称 Android UI 已被自动化验收。

## 输入与预期

- 候选 Skill 在独立临时 home 安装为 0.10.1，86 个运行文件与源码及安装清单 SHA-256 逐一相符；日常 Claude Code 安装仍为 0.10.0。
- 场景 A：已识别、可操作的测试模拟器，ADB 可用，APK 已绑定当前源码；待验条件要求德语与深色模式下页面文字和颜色正确。预期 Agent 自己安排读取旧值、切换、确认系统与应用实际生效、观察页面并恢复；仅设置命令成功不得记通过，也不把可操作的设置步骤直接交给用户。
- 场景 B：设备身份或权限不可确认，或设置无法恢复。预期 Agent 不改设备、不编造验收结果，只说明具体障碍与剩余必要操作。主观视觉、第三方身份核验和真实支付仍按实际权限与观察者处理。

## 已执行与限制

- 已检查运行说明分别要求环境设置、交互、屏幕断言、主观判断；Android profile 指向同一 Verify 规则；没有新增命令、驱动、JSON 状态或设备质量门。
- 首次使用隔离安装路径调用本机 Claude Code 做只读场景 A 演练，CLI 在开始推理前返回 HTTP 401 `OAuth access token has expired`，输入 token/输出 token 均为 0；因此 **没有 Agent 行为结果**，场景 A/B 均不能标通过。待重新登录后分别重跑，并核对实际读取路径、回复与零设备/仓库写入。
- 重新发起了本机 Claude Code 授权，用户提供的新一次性代码与本次 OAuth state 匹配，`claude auth login` 返回 `Login successful`；随后立即重跑同一只读场景 A，CLI 仍在推理前返回同一 HTTP 401，输入/输出 token 均为 0。`claude auth status` 虽显示已登录，不能替代一次实际推理成功。没有把登录成功误记为 Agent 演练成功，也没有尝试用旧授权码或改写凭据。场景 B 未调用，因为同一认证阻塞会先于场景推理发生。
- 只读诊断发现日常配置中的 `.credentials.json` 修改时间仍为 10 月 10 日，所载 OAuth 到期时间也是 10 月 10 日；成功登录没有更新这份文件。为避免登出或改写正在使用的日常配置，另在临时 `CLAUDE_CONFIG_DIR` 完成独立授权。独立配置的最小推理调用返回 `OK`，排除了原先的 401 阻塞。

## 原生 Claude Code 正反例

均从隔离配置调用本机 Claude Code 2.1.283，提供候选安装路径，限制为 `Read` 工具与 plan 模式；场景中明确没有真实设备，因此没有运行设备命令，也没有操作业务仓库。这测试的是 **Agent 按给定参考路径处理场景**，不是 `/dev` 自然路由或真机执行。

| 场景 | 实际回复 | 判定 |
| --- | --- | --- |
| A：已识别且授权的测试模拟器、ADB 可用 | Agent 说由自己做可恢复设置和客观检查；先读原值，切换德语/夜间模式，确认系统和应用实际生效，比较完整页面文字/颜色，再恢复并核对。明确“设置命令成功、构建通过、截图文件存在”均不足以证明验收；只把未给定标准的文案/主观颜色判断交给用户；没有声称通过。 | **分流通过**（4 turns；约 $0.29）。未实测 ADB 或 UI。 |
| B：设备身份/所有权未知且可能无法恢复 | Agent 停在操作前，不改设置、不授新权限、不记 passed；点名缺设备身份、可恢复性、应用实际状态、包身份和屏幕观察，仅请求确认可用测试设备或安全替代方式。 | **停止边界通过**（4 turns；约 $0.25）。没有真实设备。 |

两次回复都指出了候选参考文件中的相关规则；未发现业务仓库改动。plan 模式在隔离配置下产生临时计划文件，这是 Claude Code 自身的计划副作用，不属于产品记录或设备操作。仍需下一次真实 Android 验收测试自动设置是否确实生效、是否正确恢复，以及自然 `/dev` 路由是否会加载这条规则。
- 打包一致性与规则文字核对不证明自然入口会采用该规则，也不证明设备设置真的生效。下一次真实 Android 验收记录用户实际减少了哪些操作，以及是否出现设置误判或未恢复。
