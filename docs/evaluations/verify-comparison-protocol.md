# Verify 独立上下文对照协议

状态：待执行。此协议用于决定是否把 Verify 从现有单 Agent 流程隔离；它不是多 Skill 已上线的证据。

## 同条件输入

选择一项已有明确需求、代码改动和验收记录的真实功能。先在临时只读副本冻结 Git 修订、Skill 版本、原始来源、需求/决策/任务/影响/修复记录、质量报告及其他本机证据。生成文件清单和 SHA-256；逐项标出存在、缺失与不可读。两组拿到完全相同的副本和清单，不从开发者的口头总结补充事实，也不把答案藏在提示里。若一组输入缺失或变化，则该轮不作准确率对照。

## 两组试验

- A：按现有 `/dev` Verify 阶段在原开发会话继续复核。
- B：全新独立上下文，只接收冻结副本、同一问题与同一证据清单，不接收 A 的发现或结论。

尽量保持模型、Skill 版本、工具权限和时间范围一致。两组均只读：检查需求与代码差异、共享资源/调用方、保留行为、测试断言、人工验收缺口和证据版本；不得修改业务项目或原验收记录。若原开发会话无法重建，仍可做独立复核，但只能作为案例，不能称为严格 A/B 对照。

## 记录与裁决

分别保存输入清单、起止时间（包括阅读、交接和报告）、可取得的 Token、读取文件、每条发现的路径与证据、未覆盖范围、需要人工介入的次数。由维护者对两组发现逐条核对原始文件和运行证据，标为确认发现、误判或证据不足；原开发报告也不能自动当作真值。人工目视、自动测试和推断分开记；装机版本不明时不作版本绑定的通过结论。

对比新增有效发现、遗漏、错误断言、交接损失、误阻塞、总时间与 Token。至少重复于不同类型的真实需求后，再决定独立 Verify 是否值得实施。仅发现一个新问题，或仅缩短提示词，都不足以证明拆分收益；若独立组持续减少重大遗漏且交接与成本可接受，优先试行 Verify，保留一个用户入口及现有 JSON 权威记录。其他阶段继续按各自证据决定。

2026-09-24 的 [OGFR-2577 试演](../reviews/2026-09-24-ogfr2577-independent-verify.md)不满足同条件双组与完整成本记录，因此只用于制定本协议，不进入对照统计。
