# 0.5.34 临时写入范围补强：个人原生隔离复检（2026-09-30）

## 要验证什么

[前次跨会话演练](2026-09-29-cross-session-revision.md)核心需求接续通过，但 Agent 自建提案与故障副本曾写入授权项目之外的系统临时目录。0.5.34 只补执行位置和拒绝后的停止规则，不改业务门禁、命令、Python 脚本或权威记录结构。本轮检查原生 Claude Code 是否实际读取并遵守新提示，而不是只检查文字存在。

使用冻结的 0.5.34 插件副本 `featrace-write-scope:dev`，三个独立项目副本各开一条全新原生会话，通过 Skill 工具执行 `next --feature RESUME-001`。宿主提示仅允许项目内写入与项目外预定的 `assessment.md`；没有授权 Agent 自建系统临时文件。项目外 assessment 是演练指定输出，不算随意临时目录。详细调用筛选、前后文件哈希与原始摘要见 [证据目录](evidence/2026-09-30-write-scope/audit.json)；各轮 prompt、assessment、日志、提案及拒绝注入另行保存并有 [哈希清单](evidence/2026-09-30-write-scope/manifest.json)。

## 边界与下一步

这是三个合成项目、单机 Claude Code 的**采用证据**。钩子是演练注入，不是操作系统权限封锁；第二次拒绝也覆盖了本可在内存中执行的命令，所以不能据此证明所有替代路径均无法执行。规则仍靠 Agent 遵守，宿主沙箱/权限与实际工具调用审计才是强隔离。没有实测并行 Worker 或独立 Verify 的外部授权分支，也没有衡量真实需求的时间收益、跨机恢复或全自动交付。
