# 安装版 Verify 同输入对照（2026-10-08）

## 结论

在两个冻结的合成输入上，普通单 Agent 和独立 Verify 都正确识别了缺陷例中的收据回归，也都没有把修复后的正确代码判为当前缺陷。独立 Verify 没有增加有效发现；两例合计墙钟从 148.6 秒增加到 223.5 秒，Claude CLI 估算费用从 $0.909 增加到 $1.490。保持独立 Verify **可选**，不据此改为默认，也不扩大 Skill 拆分。该结果只针对这两个小型合成输入，不证明真实需求上的准确率或净收益。

## 输入与运行约束

- 安装源：`/Users/mac/.claude/skills/dev`，安装标记版本 **0.5.37**，76 个运行文件的标记哈希与安装文件一致。两组均用 Claude Code CLI 2.1.283、`claude-opus-5-5`、medium effort、相同工具集与 $3 单轮上限；独立组额外使用该 Skill 的原生 Agent 派发和交接核对。部分 Agent 从单个 reference 标题误报 0.5.24/0.5.35 或称“无版本”，裁决采用安装标记，不能把这些标题当安装版本。
- 两个案例都来自 `tests/fixtures/independent-verify/create_fixture.py` 的 DEMO-PREVIEW。`case-1` 的 HEAD 为 `1fb70a0`：共享常量从 12 改成 8；`case-2` 的 HEAD 为 `4d41b8b`：新增 `PREVIEW_LIMIT=8`，收据仍用 12。每个案例的单 Agent 和独立组拿到**同一份**项目快照、11 个文件的 SHA-256 清单和中立问题；两组串行运行且互不读结果。第二例先跑独立组，再跑单 Agent，避免顺序只偏向一个方法。
- 单 Agent 走普通 `/dev check DEMO-PREVIEW` 路径且不派发；独立组走 `--independent`，实际分别派发 1 个全新上下文 Agent，完成 `VERIFY_HANDOFF_CURRENT` 预检及 `VERIFY_REVIEW_RETURN_CURRENT` 返回核对。四组都禁止项目写入、构建、测试和交付，只比对只读审查。运行后两份项目的 Git 状态仍干净、HEAD 未变，清单内 11/11 文件哈希逐项匹配。
- 本次无法复现原开发会话中的普通 Verify，因此 A 组也是新会话。按[对照协议](verify-comparison-protocol.md)，这是**同输入架构对照**，不是严格的“原开发会话续审 vs 独立审查”A/B。缺失的 `layout.png` 和自称合成的质量报告在两组中相同；它们是已知证据缺口，不是某一组新增发现的优势。

## 逐项裁决

| 冻结案例 | 单 Agent | 独立 Verify | 维护者独立核对 |
|---|---|---|---|
| `case-1`：存在收据回归 | 找到共享 `DISPLAY_LIMIT` 对 `src/receipt.py` 的影响；指出短输入测试无辨别力、测试与质量证据缺口 | 找到同一回归与相同主要证据缺口；交接结果保留了调用方 | **两组均命中，重大遗漏 0**。无字节码写入地运行样例函数：16 字符输入的预览与收据均被截为 8；PRD 要求收据保持原行为，基线为 12。追溯记录漏了受影响调用方。 |
| `case-2`：代码已修正 | 判定预览 8、收据 12；指出测试断言存在但无实际运行证据 | 同样判定代码正确，并指出中间提交曾有回归、HEAD 已消除 | **两组均未误报当前代码缺陷**。同样输入的预览为 8、收据为 12；`tests/test_preview.py` 已有两条相关断言，但质量报告不是实际测试结果。 |

两组均如实标出缺失的设计源、逻辑测试 ID 没有明确执行映射、合成质量报告不能证明交付。独立组在 `case-2` 还写了“`traceability.code` 列出未修改的 `src/receipt.py` 是记录准确性问题”。[需求记录说明](../../skills/dev/core/references/requirement-schema.md)将该字段定义为需求到代码的关联，并未限定只登记本次修改的文件；这是**1 条依据不足的轻微附加判断**，不计为真实缺陷。单 Agent 的“边界测试较薄”只是额外建议，已有长输入断言足以区分本夹具的 8/12 回归，不计阻断缺陷。

## 可复核证据与限制

[冻结输入、逐组提示、原始结果与用量](evidence/2026-10-08-verify-same-input/)在仓库内；包含每例 11 个合成文本文件内容、清单、base→HEAD 补丁、四份结果、独立组快照和路由裁决。CLI 原始流、登录失败输出和本机认证配置留在临时目录，不入库；若临时目录被清理，仓库证据足以复核输入、结论和返回的摘要指标，但无法逐工具重放完整事件流。

两个输入结构相近，且刻意包含已知回归与修复；样本量、真实项目复杂度、原开发会话背景均不足以估计实际遗漏率。评估禁止两组运行测试，因此这里只裁决审查识别能力；维护者事后运行的函数样例是**裁决证据**，不是 Agent 的测试成绩。下一笔真实需求仍按普通入口交付，记录独立复核能否新增有效发现、误判和总成本后，再考虑是否改变默认策略。
