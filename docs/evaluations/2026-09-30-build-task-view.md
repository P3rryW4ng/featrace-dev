# 0.5.36 Build 任务视图的源仓验证

日期：2026-09-30。范围仅为现有两个独立大小写任务的合成夹具与确定性脚本；未启动新的 Claude/Codex Worker，不是上下文或开发效率 A/B。

## 改动与实测

- `parallel-build.py task-view <RUN> <TASK-ID>` 在原有完整 preflight 后，从冻结输入投影指定任务的已确认需求、明确相关及无关联标签的决策、保留行为、影响机制、追溯和复核摘要。原记录保持权威；发生关联不明或新调用方时，Worker 可回读冻结原件并交回 Scope。
- 同一夹具中，完整 `run.json` 为 **8,129 字节**，T-UP 的紧凑 JSON 视图为 **4,345 字节**，约为前者的 **53.5%**。这是一次打印输出的字节数，不能换算为实际 Token 节省；Worker 仍需读取原始 PRD、相关代码及测试。
- 目标回归覆盖本任务选择、明确无关项过滤、全局决策与跨任务保留行为不被过滤、记录变化影响摘要、复核索引损坏与软链接拒绝、冻结输入篡改拒绝及 CLI 返回。`test_parallel_build` 24/24 通过；完整 unittest **272/272** 通过（最后一轮 72.912 秒）。
- Skill Creator 的 `quick_validate.py` 因本机 Python 缺 PyYAML，在导入阶段退出，**未通过**；三个 Skill frontmatter 另用 Ruby YAML 解析成功。`git diff --check` 通过。

## 结论边界

源码脚本能提供较小的任务起点，并保持原有过期/越界/集成门禁；不能证明 Agent 实际少读文件、少用 Token、减少遗漏或并行更快。这个视图是指令层面的读取起点，不是文件系统权限隔离；用户及项目授权边界保持不变。个人 Claude Code 后续已安装 0.5.36，76 个运行文件与源码一致；安装版 Agent 采用仍未执行。下一步按路线图对冻结相同输入做单 Agent 与独立专家对照，再在真实需求观察净收益。
