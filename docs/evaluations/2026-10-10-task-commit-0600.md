# 0.6.0 安装版任务级提交隔离演练（2026-10-10）

目标：观察 Claude Code 是否真的按总路由的 Build 收尾规则，在一个需求的任务尚未全部结束时分别提交；同时核对已有暂存内容能否阻止不安全的自动提交。项目是 `/private/tmp` 下的合成 Python 夹具，不是业务仓库；两轮均从新 Claude Code 会话加载本机 `/dev` 0.6.0。

## 正例：T-1 完成，T-2 未开始

- 夹具需求 `FEAT-001` 含两项任务：T-1 去除收据备注首尾空白、T-2 将徽标文字转为大写。起点提交 `b86a01e` 仅登记已复核范围；T-1 的代码和任务记录留在未提交工作区，T-2 仍为 `planned`。
- 安装版 Agent 运行 `python3 -m unittest discover -s tests -v`：1 个聚焦用例通过；`validate-feature.py --stage develop` 返回 `FEATURE_VALID`。它全文查看暂存差异并运行 `git diff --cached --check`，随后创建 `da965b6`：`feat(FEAT-001/T-1): trim surrounding whitespace from receipt note`。
- 提交只有 `src/receipt.py`、T-1 所在 `tasks.json` 及两份生成视图，共 4 个路径。提交正文区分 Why、Checks、Pending；T-2 仍为 `planned`，`badge()` 未改，未运行整需求 check/audit，未推送或宣称需求完成。Agent 渲染视图时产生的两处无关纯空白变更由它撤回，未进入提交。

## 负例：T-2 已实现，但索引中另有暂存内容

- 复制正例结束时的夹具，在工作区完成 T-2 的代码、测试与任务记录；另把无关的 `README.md` 修改预先放入暂存区。两项聚焦用例通过，develop 结构校验返回 `FEATURE_VALID`。
- 全新安装版 Agent 查看状态和 T-2 差异后，只运行聚焦测试（2/2）；它识别 `README.md` 与 T-2 无关，**没有提交**，没有暂存/撤销暂存/重置该路径，也没有推送或运行最终 check。T-2 的工作区修改保留，视图仍待更新。
- 这验证的是保守停止，不证明自动解除冲突；需先处理既有暂存内容或另行明确授权安全的路径限定提交。

## 结论与边界

安装版 Agent 在两条定向指令下遵循了“任务完成就本地提交、整需求验收分开”以及“已有无关暂存则停止”。提交说明可读且未把 T-1 写成整需求完成。此处没有测试多个 Worker 的采用后拆分、真实项目的 Git 钩子耗时、普通自然对话触发率或长会话中状态保持；也没有测量 Token 和完整墙钟。后续真实需求须记录任务数、实际提交范围与时点、聚焦检查耗时、Git 钩子耗时、阻塞次数和最终 Verify/Deliver 结果，不以本夹具代替交付收益。
