# GAP-18/19：已安装 Claude Code 的隔离模块图复检

日期：2026-09-30。目标是观察本机安装版 `dev` **0.5.35** 在 Agent 正常调查中的采用行为，而不是重复声明脚本单测通过。两个新 Claude Code CLI 会话分别收到普通 `/dev scan` 请求；提示没有点名 `:external`、`:debugkit`、GAP 编号或预期结论。运行前核对安装标记的 75 个文件哈希均匹配。调用轨迹显示 Agent 实际读取 `/Users/mac/.claude/skills/dev` 中的 `project-baseline.md`、`module-context.md` 等规则，并调用该安装包脚本；导出的工具事件没有单独的 `Skill` 工具条目，因此此处只认定**安装版规则与脚本被 Agent 使用**，不把工具事件缺失说成已观察到独立 Skill 派发。

## 固定合成输入

[完整的八个输入文件](evidence/2026-09-30-gap18-19-installed/fixture/)是无 Gradle wrapper、SDK 和业务测试的最小 Android 声明夹具：`settings.gradle.kts` 只包含 `:app`、`:identity`、`:debugkit`；`app/build.gradle.kts` 第 3 行是到 `:identity` 的普通依赖，第 4 行指向**未包含**的 `:external`，第 5 行通过 `add("${flavor}Implementation", project(":debugkit"))` 表达条件依赖。源码仅有三个简单类。两个项目副本都在 `/private/tmp/`，没有访问真实 Android 项目或改动源仓运行包。

第一次从空工作流目录扫描。第二次复制其产物，先在隔离副本 `modules/index.json` 中**故意**把 `debugkit` 加进 `app.depends_on`，形成有错的正式无条件关系；[注入前目录](evidence/2026-09-30-gap18-19-installed/injected-wrong-index.json)留档。维护者在 Agent 启动前独立运行已安装脚本，`module_context.py graph` 退出 1，报 `conditional Gradle dependency :app -> :debugkit cannot be recorded as unconditional depends_on; review app/build.gradle.kts:5`。此注入属于实验条件，不算自然项目缺陷。

## 判定与边界

GAP-18 的“未知目标导致候选图整批丢失”和 GAP-19 的“仅有条件声明却被提升为正式无条件关系”在这两个**安装版 Agent 隔离场景**中没有重现；反例中 Agent 收到硬错误后按源码证据纠正。可将路线图中“待安装版 Agent 复检”改为“已通过本轮隔离复检”。这不证明大型项目、动态 Gradle 表达式、真实业务模块职责或自然需求下的长期稳定性；也不测量相较旧版的准确率/提效。后续真实 `scan` 继续观察未知目标和条件关系是否被实际调查、是否误报，以及总成本。
