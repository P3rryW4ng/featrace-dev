日期：2026-10-10。被测安装目录 `/Users/mac/.claude/skills/dev`，安装标记版本 0.8.0。项目是 `/private/tmp/featrace-change-route-0jiGmN` 中临时创建的 Git 仓库，仅有一个返回前 12 个字符的示例函数；没有使用真实业务项目。

## 输入与观察

先在原生 Claude Code 交互会话发送 `/dev`，得到 `FeatraceDev ON` 和隔离项目名。随后不用 `change` 命令，直接发送普通中文描述：把既有收据标签的显示上限从 12 改为 8 个字符，其他收据行为保持不变，并明确暂未提供产品工单编号、不要改文件。

Agent 读取安装版轻量变更说明后，把请求判为独立 `change`，没有归入新 PRD 或任何已选需求；回复“轻量变更准备 · 编号：待提供 · 描述：已收到 · 模块：待调查”，只追问产品工单编号。结束后 `git status --short` 为空，项目内没有 `.agent-workflow/`；没有运行初始化、构建或测试。

在此之前另用一次 Claude Code 非交互调用询问同样的普通描述。允许只读读取安装目录后，它也判为 `change` 并只追问编号。最初一次非交互尝试因隔离调用的读取权限不足达到最大轮数，不能算行为通过；其后授权只读访问的重试成功。非交互 `/dev` 调用可启动模式，但该隔离环境中的会话恢复报告找不到该会话，故最终采用原生交互会话完成连续两消息复核。

原生会话出现本机其他插件的非阻断 Bun 钩子错误，以及隔离沙箱阻止写入 `~/.claude/session-env` 的提示；本次被测路由仍返回预期结果。这些宿主提示不能算 Skill 自身的测试结果。

## 证据边界

本次证明安装版 0.8.0 在这个合成项目的一次原生会话里，能够从普通描述进入轻量变更准备，并在缺编号时停止且不写项目文件。未给出编号，因此没有验证原话建档、既有需求归属判定、故障分流、需求评审、代码开发、质量门或交付，也没有测量相对旧入口的时间收益。真实项目采用仍需单独观察。
