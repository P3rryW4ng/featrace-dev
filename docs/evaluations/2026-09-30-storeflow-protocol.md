# StoreFlow 综合隔离演练协议（2026-09-30，结果产生前固定）

## 目的与范围

用已安装的个人 dev 0.5.34，经原生 Skill 工具，在合成既有项目中观察多模块共享消费者、库存/支付副作用、PRD 变更和跨会话接续。业务模型含预览、共享计价、下单、库存、支付、收据和旧导出；标准库 Python，无外部服务。不是 Android 真机或生产规模项目，不证明真实提效。

## 顺序

1. **部分交付点**：新会话读取已批准 PRD v1（会员折扣10%、上限2000分），建立来源/Scope/任务，只实现 preview。预先授权这个暂停点，其他任务保持未完成。默认/旧导出与原有断言保留，可在隔离项目本地提交，不 push。
2. **独立验收与冻结**：维护者核对原生调用、真实 diff、既有测试及未向 Agent 提供的黑盒契约；保留项目快照。v2 内容尚不交给 Agent。若第一段失败，记录失败及真实修复，不直接跳过。
3. **中途修订与新会话接续**：才将已批准 v2 提供给新原生会话（会员折扣15%、上限1200分，其他语义不变）。只给项目、修订和继续授权，不给第一会话摘要或隐藏验收。要求恢复项目事实、重开受影响任务、完成 checkout/原子失败保护及真实验证，最后本地报告/交付。原始PRD和旧测试证据留史。
4. **失败修复分支**：若独立验收发现失败，以实际现象交给新的 Repair 会话，不能预告根因。若正常实现全部通过，用另一次明确标记的人为故障注入制造“重复请求重新改动库存”的偏差，再独立走 Repair；该故障不能计为 Skill 自然漏出缺陷或真实收益。保留故障前后快照。
5. **收口审计**：每轮核对个人Skill未被改写、写入位置、PRD原文、旧接口和断言、任务/修订/验证历史、报告读取顺序与completion。停止/未运行/缺资料据实保留。

## 预先固定的独立契约

预览8项：默认及legacy不打折、未封顶、封顶、v1/v2区分、空预览、整数向下舍入、非法输入、重复SKU及不改原输入。
下单10项：实际收费/收据字段、默认行为、重复ID换购物篮、重复ID非法输入、已有历史收据不改、后续商品缺库存时原子失败、重复SKU总量不足、支付拒绝回滚、失败后同ID重试一次、非法/空订单不改状态（同一测试包含数种输入）。实际用例总数以独立脚本发现结果为准，不能为追求预定数字补空测试。

重点核对重复成功请求先返回原收据，无论新参数是否合法都不重复扣款或库存；异常后库存、扣款和收据缓存不变（支付模拟器 decline_next 可消耗）。共享 calculate_total 与旧导出继续返回不打折总额；副本/测试不污染主树。

## 证据与成本

保存真实 Skill/工具调用、阶段、项目快照身份、需求版本、测试日志及失败现场。墙钟、CLI用量/标价估计与维护者准备/验收成本分开；记录是否需要追加指令、源仓脚本用法摩擦、重复加载、误阻塞。人工指定暂停和后续故障注入属于实验条件，不声称零人工成本。没有自然需求对照，不计算准确率或效率提升百分比。

本轮普通 Agent 执行不请求并行/独立子 Agent；第一段明确串行以隔离部分里程碑，第二段按已安装规则且宿主可用能力保守执行。不能据此验证双 Worker 分支。
