# 0.11.0 安装版证据断言复核隔离验证

日期：2026-10-13。目标是检验安装版 Claude Code 的全新上下文复核者，能否区分“质量门通过”与“完整验收断言有据”，并观察结项路由和证据过期行为。本轮只使用临时合成 Python 项目；真实 Android 项目与 Skill 运行代码未修改。

## 输入与执行方式

- 本机安装标记为 0.11.0；源码、安装副本、标记中的 88 个运行文件 SHA-256 逐项一致。源码起点为 `0a4473d`。
- 两例都要求 `getHostUserInfo`、`getHostUserInfoAll`、`getUserInfoAll` 在输入恰为有序列表 `["de-DE", "en-GB"]` 时返回同一完整列表；需求和影响行都预先记录为 `passed`，其中反例的记录与实际行为不符。单靠结构校验和交付审计，两例都显示可通过。
- 正例 B 的单测逐一调用三个接口并断言精确输入、精确输出；反例 C 的通过单测只调用首个接口，输入还是 `["de-DE", "fr-FR"]`。反例的第三个接口实际只返回第一项，因而在目标输入上会漏掉 `en-GB`。两例的所选单测门禁都实际返回 0。
- 每例重新冻结输入，在项目内保存 capture；以新的、不继承本会话结论的 Claude Code CLI 上下文显式交给它安装版复核说明和只读项目资料。复核者只使用 Read/Glob/Grep，没有执行测试或写项目文件。先前放在项目外的 capture 使只读 Agent 无法读取，得到的返回没有有效摘要，已保留为无效预跑，未计作结果。

## 观察结果

| 样例 | 独立复核者的逐项判断 | 安装版校验与路由 | complete 状态探针 |
| --- | --- | --- | --- |
| B：精确三接口证据 | 2 条 `supported`，返回摘要与冻结输入一致 | `CLAIM_REVIEW_CURRENT`；`CLOSURE_ROUTE_DELIVER_ELIGIBLE` | `FEATURE_VALID` |
| C：近似输入且第三接口有缺陷 | 2 条 `partial`，明确指出未测接口会丢失 `en-GB`，返回摘要与冻结输入一致 | 两条未解决，`CLOSURE_ROUTE_CLAIM_REVIEW_REQUIRED` | 退出码 1，两条 claim review 错误 |

复核结果与全部必要输入见[合成证据目录](evidence/2026-10-13-claim-review-installed/)。两例的来源原文、代码、实际断言、已登记结果、质量报告、冻结 capture 和独立返回均保留。反例说明 `FEATURE_VALID` 和 `DELIVERY_EVIDENCE_CURRENT` 只证明既有结构检查满足，不能代替断言语义判断。

在正例副本上分别改变原始 PRD、测试文件、已登记验收证据，旧复核均被判过期；恢复后重新变为 current。只改质量门 `selection_reason` 的说明文字，复核仍为 current，避免无关措辞引发重复验收。另用一个**人为写绿**的探针确认：结构检查可以接受语义上不足的 `supported` 返回；因此复核者的判断质量仍是必要条件，脚本本身不保证结论为真。

最初还试过只有单接口测试、但三个接口实现完全相同的纯函数样例。独立复核者基于源码确定性推导判 `supported`，并说明运行覆盖的局限。这并非误放行：代码足以推出该输入下的结果。为测试真正的错误完成声明，才加入第三接口实际截断的反例 C；没有把原样例强行算作失败。

## 时间、成本与边界

最终有效的正反例 Agent 调用分别约 33.9 秒、37.8 秒；Claude CLI 报告的估算成本分别为约 $0.498、$0.511，合计约 71.7 秒、$1.009。前期为了修正夹具和只读交接另发生三次模型调用，约 146.0 秒、$1.731；五次成功调用总计约 217.7 秒、$2.740。登录过期造成的失败尝试没有模型 Token；墙钟等待不计入上述调用时长。以上是隔离试验成本，不能外推成真实需求的净成本或节省。

本轮是**显式派发的合成 Python 任务**，没有验证普通 `/dev check` 会自然启动独立复核；也没有让 0.11.0 在 OGFR-7700 的真实原始快照和最终快照上审查，未涉及 Android 设备、JS 容器或真实业务结项。它证明这两例中独立复核者区分了具体反例和有据结论，且安装版能阻断反例、保留过期边界；不证明真实误结项率下降，也不代表第二阶段完成。
