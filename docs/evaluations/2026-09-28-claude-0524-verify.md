# Claude Code 0.5.24：独立 Verify 宿主隔离复检

日期：2026-09-28。目标是确认个人安装版实际采用判断规则和路由派发前停止；不验证全自主交付、不默认推广独立 Verify、不启动并行 Build。

## 环境和方法

- 个人安装 `/Users/mac/.claude/skills/dev` 为 0.5.24；执行前后 70 个文件与仓库源码及安装标记一致。宿主 Claude Code CLI 2.1.283，执行记录模型为 `claude-opus-5-5`；未指定或切换模型。
- 从仓库 independent-verify 合成夹具分别创建三个临时 Git 项目，A/B 补逻辑测试 ID 的执行映射；B 分离预览八字符常量和收据十二字符常量并加两条相应断言。A/B 均保留 feature provisional、R-1 confirmed、空 decisions、缺失 layout.png 及明确自标的模拟质量报告。
- 每例都是新的 CLI 会话，不续接先前会话；实际使用个人安装 Skill。只给中立问题、对应路径/基点、指定快照和只读限制，不给预设答案。A/B 总路由各实际调用一次 general-purpose Agent，派发参数只含专业规则、绑定路径、中立问题和限制，没有传入疑似缺陷或绿色结论。
- C 捕获后仅在自己的忽略 PRD 中追加文本，继续指定旧快照，禁止重捕获。全程串行执行，单次 CLI 设置预算上限 5 美元，没有无限重试。
- 先用过窄权限运行 A，Bash 预检和外部 Write 被主机拒绝，41.316 秒后在路由层停止，没有 reviewer。保留该尝试；修正工具授权后另建 A2，未覆盖旧产物。本项属于演练权限配置，不记为 Skill 的语义失败。
- 最终尝试允许所需 Read/Glob/Grep/Bash/Write/Agent/Skill 工具；只读由指令约束，不是 OS 沙箱。关闭额外 MCP 与 Chrome，禁止测试/构建、修复、业务记录更新、安装和提交。执行前后对全部项目普通文件（包括忽略来源/质量报告）作 SHA-256 对比，并检查 HEAD、Git 状态和安装文件；均未改变。哈希一致不证明未发生过短暂写入。

## 核对结果

| 场景 | 实际观察 | 判定 |
|---|---|---|
| A：实现有回归 | 独立复核发现共享 DISPLAY_LIMIT 从 12 改到 8 导致 receipt_reference 缩短；引用原文、confirmed R-1、基点/当前代码。恢复旧行为被正确归为实现修复；不因 provisional 或空 decisions 要求重新产品拍板 | 指定缺陷被发现，四类旧误推断未再现 |
| B：当前实现正确 | 确认 PREVIEW_LIMIT=8、DISPLAY_LIMIT=12，收据未变；识别两条映射用例和实际断言，但明确没有执行。不报告当前实现偏差、不捏造 ID 缺失或需求未确认 | 本例无当前实现误报 |
| A/B：证据不足 | 均报告索引图片缺失、质量报告自标 synthetic；A 识别短输入仅部分覆盖，B 识别已有两条有效断言及可加强边界；没有更新 verified/complete | 缺口没有被补猜或冒充通过 |
| C：预先过期 | 路由预检退出 1，review inputs stale；流式轨迹没有 Agent 调用，只有 router assessment，result.json 不存在。维护者复跑也退出 1 | 已知过期请求没有启动 reviewer |

A/B 的返回检查均退出 0、VERIFY_REVIEW_RETURN_CURRENT。维护者读取原始 JSON、源码、测试映射/断言、路由 assessment 及调用轨迹，核对引用，不采信只说“成功”的文字。JSON current 不证明语义正确或交付通过。

B 的 findings 非空，含已解决的中间提交问题、记录/证据缺口和覆盖说明。中间提交确实曾改错，当前 HEAD 已恢复；不能按 findings 数量把正确实现判失败。相关中间提交依据可在路由 git show 轨迹中核对，但 JSON 引用没有独立表示该中间修订；结构检查不解决这类引用粒度问题，本例按当前行为判断并保留限制。

C 在预检失败后又跑了一次只读 verify-inputs 盘点，并没有继续业务语义复核或派发。所以证明的是“不再派发无效 reviewer”，不是“失败后立即结束所有工具调用”或最低开销。

| B | 175.368 | 83,414 | 26,179 | 0.580906 |
| C | 79.187 | 无派发 | 无 | 0.283786 |

外层时间覆盖 CLI 启动、准备、派发、主路由裁决和写结果，不含维护者造夹具、额外核对及文档整理。Agent 毫秒/token 来自 CLI 工具返回 usage，主路由有更大重复输入/缓存成本；各指标不能混用或直接相加作上下文长度。costBasis=list 是 CLI 标价估计，不是 Team 账号实际扣费。三例正常尝试共 430.078 秒；另有最初权限受阻 41.316 秒及 0.297447 的 CLI 标价估计，不能从总演练成本隐去。

此前 0.5.23 的用户反馈与本次宿主、模型、权限和用例细节并非严格同条件 A/B；即使子 Agent token 数更小，也不能声称总体变快或成本降低。两个很小的正常案例仍各耗约三分钟，说明默认推广和进一步拆分前必须评审总成本。
