# 0.5.25 两任务隔离 Build 原型验证

日期：2026-09-28。用户授权范围：明确两个独立任务、复用一个 Build 专业 Skill、分别隔离代码、总路由汇总，合并后检查。默认仍串行，不扩大其他阶段。

## 实际机制与权限

源码增加 `parallel-build.py`、`parallel-build.md` 和 `specialists/featrace-build/SKILL.md`。prepare 复用现有输入快照和 develop 校验，冻结来源/记录，检查任务与文件归属，再创建两个 detached 工作区；finish 生成各任务补丁并真正运行选定命令；integrate 重核返回，在第三工作区应用补丁并运行集成检查。主项目采用、共享记录串行更新和普通 Verify 是后续步骤，不被候选通过替代。

独立审查找到并修正四处边界：非规范路径可能掩盖重叠；冻结库存新增未检测；Git 检查故障被误标冲突；非对象临时记录报 traceback。另把 worker 可见文件与真实索引绑定到检查结果，拒绝检查期间或之后的变化。最终记录摘要检测漂移，不是签名，也不证明语义独立。

## 确定性与故障验证

目标测试 21/21 通过（25.033 秒）；最终完整回归 **265/265 通过（69.371 秒）**。完整执行输出见 [full-tests.txt](evidence/2026-09-28-parallel-build/full-tests.txt)。

| 场景 | 实际结果 |
|---|---|
| 两任务各自通过并集成 | candidate_checks_passed；主项目代码、记录、HEAD/索引保持不变 |
| 重叠/依赖/非规范路径 | 创建工作区前拒绝；文件不同本身不证明业务独立 |
| 越界或改共享记录 | finish failed；不创建集成候选，保留改动 |
| 任务失败/缺失返回/命令不可用 | 拒绝集成，不把缺失结果当通过 |
| Git apply 冲突 | 控制外部写入制造真实补丁应用失败；merge_conflict，保留候选 |
| 合并后测试退出 4 | checks_failed，保留候选，主项目不变 |
| 集成检查改变可见输入 | blocked，拒绝以原测试背书被修改候选 |
| 来源变化、冻结库存新增、补丁/索引/日志变化 | 旧结果拒绝采用 |
| 检查 Git 操作不可用 | blocked，区别于补丁冲突 |

故障矩阵由独立临时 Git 项目与真实命令验证；部分故障通过受控注入触发。它们不是 Claude 的多轮失败处置行为评估。

## 两个实际独立 Agent

准备另一份合成项目：原始 upper/lower 函数均原样返回字符串；已确认要求分别转大写/小写，两个既有断言初始不满足。主路由审阅两个无共享状态的入口，完成 prepare；两个 Codex Agent 使用全新无历史上下文，各自读取同一个 Build 专业说明、自己的任务和冻结资料。派发没有给出实现答案，不允许写主项目、同伴或共享记录，也不允许提交或集成。

维护者回读实际补丁和日志，而不是只采信 Agent 自述：

- T-UP 只改 upper.py，使用字符串大写转换；选定单测真实运行 1/1 通过。
- T-LOW 只改 lower.py，使用字符串小写转换；选定单测真实运行 1/1 通过。
- 两者各调用 finish 一次，返回 ready；同伴文件分别与基点一致。
- 等两者停止后，主路由集成到第三工作区，真实运行 2/2 通过，candidate_checks_passed。
- 主项目所有可见文件、工作流记录及索引状态与准备前完整比较一致；HEAD 仍为 f05d544a78dc5ff2fea158626c8a8d673e3594c4。未应用主项目，未标 task done/feature complete。

实际返回、补丁和检查见 [证据目录](evidence/2026-09-28-parallel-build/assessment.json)，包括 [T-UP 返回](evidence/2026-09-28-parallel-build/T-UP-result.json)、[T-LOW 返回](evidence/2026-09-28-parallel-build/T-LOW-result.json) 与 [集成报告](evidence/2026-09-28-parallel-build/integration-report.json)。集成 helper 墙钟约 0.614 秒；未采集全过程、Agent token 或实际费用。Agent 报出的 0.5/0.41 秒是工具耗时，不能当作端到端开发时间，更不能宣称比串行更快。

## 限制与下一步

这是源码 0.5.25 的 Codex 独立 Agent 合成演练，**不是个人 Claude Code 0.5.25 已安装或已采用**。本机 Claude 仍为 0.5.24。本轮未提交、推送、安装或改真实业务项目；未实现自动主项目接管、调度、重试、清理或远端交付。

工作区隔离不是安全沙箱：普通 Git worktree 共享元数据，Agents 的限制来自指令与宿主权限，检查只能发现已绑定的最终变化。忽略环境、外部依赖、短暂改写和跨文件语义风险不被完全覆盖。无共享状态的微小合成例不能证明复杂任务适合并行。

通用 quick_validate 对主 Skill 和 Build 专业说明均因本机缺少 PyYAML 无法启动，不记为通过；另核对 frontmatter、运行文件引用和差异空白。下一步先按授权发布/安装，再在 Claude 的隔离项目核对普通总路由实际派发、失败返回与总成本，随后仅在有真正独立任务的自然需求中试用。独立 Verify 要在所有写入 worker 停止并完成主项目采用后，绑定新的实际交付快照执行。
