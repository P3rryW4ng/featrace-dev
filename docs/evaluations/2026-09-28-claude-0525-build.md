## 结论与证据等级

**指定并行机制通过；Scope 前置规则采用不完整，不能宣称整个交付流程已可靠。**

每个项目起点的 upper/lower 函数原样返回字符串；来源确认两个独立转换及不变输入/空串/组合行为。两个任务只有自己的精确文件归属；预先提供可读来源、intake、任务、追溯和影响清单，没有让 Claude 重做真实需求。故此不覆盖新需求创建、完整 Scope 建立、主项目采用和最终 Verify。

所有项目的可见文件、工作流记录含忽略来源、HEAD、索引和 Git 状态由维护者与执行前快照完整比较，均不变；成功/失败候选均保留在各自外部工作区，Git worktree 元数据有预期新增。个人安装 73 文件无变化。每个运行只有两次 finish 和一次 integrate；C 均为零。维护者重新运行安装版 preflight，回读补丁、日志并核对返回摘要、实际 worker 状态及 candidate Git tree，不只采信 Claude 总结。

## 启动参数导致的发现问题

初始 A/B/C 为排除个人配置使用 `--setting-sources ''`。启动清单无 dev，Skill 工具确实报 Unknown skill: dev；Claude 随后直接读取安装副本。它们支持内部链路/失败处置，不支持原生入口验收。

补充只读发现测试启用 `--setting-sources user` 并仅对当前进程禁用 hooks，启动清单出现 dev，/dev help 实际加载个人 Skill。另建 A2 新项目补跑原生 /dev develop，不复用初次候选。A2 的原生加载发生在用户命令展开阶段，没有再次调用 Skill 工具；启动清单、加载后的消息与实际规则读取共同支持入口结论。

未修改个人设置或插件；正常用户配置会加载既有插件说明，MCP 和 Chrome 在这些命令中禁用，允许工具仅用于本次演练。初始 Unknown skill 不应被误记为安装缺陷，也不能隐藏初次运行成本。原始完整流在项目外临时目录，仓库不保存个人配置或登录资料。

## 两个 worker 与集成

A/B/A2 总路由均从本地代码、既有来源及精确 plan 审阅独立性，再创建两个 detached 工作区。两次 Agent 调用在同一条消息中以后台方式发出，复用 `specialists/featrace-build/SKILL.md`，分别给自己的任务、工作区、RUN、冻结资料和限制，没有给实现答案。实际补丁分别只改 upper.py 为大写转换、lower.py 为小写转换；检查后同伴文件仍为基点版本。

两个 Agent 停止后，总路由读取各自补丁/日志，再运行安装 helper integrate。维护者确认候选确有两项变更；四个集成用例覆盖大写、小写、组合与空输入。B 的额外命令明确用于受控失败模拟，不是实际业务缺陷；退出码 4 真实记录，空日志保留，没有被其他已通过结果掩盖。

## 本轮发现的采用缺口

1. **Scope 前置规则加载不完整。** 原生 A2 实际读取主 Skill、parallel-build 和 Build 专业说明，却未加载总路由 contract、workflow、impact-review、task-semantic-review、historical-regression 等按普通 develop 约定应使用的规则。它读了实际记录与代码并执行结构校验，但不能据此说普通 Scope 前置流程已完整执行。应先明确并行路径如何接续既有 Scope 检查，再做窄范围采用复检；不靠全面预加载所有文档解决。
2. **夹具不是现代新需求全门禁样例。** fixture 的兼容模式没有强制历史回归和任务语义登记；validate/prepare 输出两条 missing review 警告但允许通过。各次没有权限修改 canonical 记录，Claude 如实保留缺口，也没有把候选应用到主项目。它证明兼容夹具上的并行机制，不证明正式新需求前置缺项可被忽略；真实项目采用前仍须当前 Scope 依据。
3. **B 中一次预检顺序偏差。** T-UP 在 preflight 前读取 run.json；其后预检通过，业务代码读写前的版本仍 current。这是说明执行顺序的偏差，记录保留；不由这一次微例宣布任意资料读取都被强制拦截。

本轮不改运行代码、不自动补造缺失 review，也不关闭这些采用限制。共享记录单点写入、普通 Verify 和最后交付没有在本例发生；原型依然按显式选择使用。
