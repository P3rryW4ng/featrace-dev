# 0.5.43 安装版会话提示隔离复核

日期：2026-10-09。范围是 Claude Code 的当前对话模式提示，不涉及业务需求、代码开发或真实项目验收。源码与本机安装均为 0.5.43；安装器核对 78 个运行文件与安装标记哈希一致。旧版 0.5.42 经安装器备份。

在 `/private/tmp/featrace-mode-rehearsal-20261009/` 用 Claude Code CLI 建立新会话，之后恢复同一个会话连续输入。最终可恢复会话中的观察如下：

| 输入 | Agent 实际回复与动作 |
|---|---|
| 第一次 `/dev` | 首行 `FeatraceDev ON · 项目：… · 需求：未选择`；只读检查项目中没有需求，未创建工作流记录或扫描代码 |
| 同会话再次 `/dev` | 首行仍为 ON；明确说只刷新状态，1 轮完成，未调用工具、未推进 `next` |
| `dev off` | 单行 `FeatraceDev OFF`；未写项目记录 |
| 退出后的普通问候 | 普通回复，无 ON 提示 |
| 再次 `/dev`，随后普通问候 | 重新显示 ON；模式内的非开发问题也保留首行提示，其正文仍按普通问题回答 |

临时项目未生成 `.agent-workflow/` 或业务文件；`activate-v5.jsonl`、`repeat-v3.jsonl`、`off.jsonl`、`after-off.jsonl`、`reactivate.jsonl`、`active-ordinary.jsonl` 保存了本次 CLI 返回。它们位于系统临时目录，可能被清理，不作为长期仓库产物。

最初的 CLI 尝试遇到网络重试；另一次虽返回了 ON，但因为演练环境没有给 Claude Code 的会话存储目录写权限，后续 `--resume` 报 `No conversation found`。补齐网络及临时会话存储权限后重建会话，才取得上述连续输入证据。这个环境问题没有被算作 Skill 行为通过。安装器首次在受限执行环境中无法移动旧安装目录，经授权后按备份流程成功更新。

结论：已观察到安装版 Agent 在一条可恢复的 Claude Code 会话中显示进入、重复查询、退出和再次进入状态。它仍只是模型遵守规则生成的一行文字；不是 Claude Code 的持久状态灯，不能保证新会话、上下文重置或宿主未加载 Skill 后继续显示。未验证带有已选需求 ID 的长会话、项目切换及真实业务开发中的每一条回复。
