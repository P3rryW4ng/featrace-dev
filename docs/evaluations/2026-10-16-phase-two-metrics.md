# 第二阶段最小指标字典与数据来源（2026-10-16）

状态：用户授权的维护准备，未开发采集器/报告器，未安装、发布或推送。不是运行Skill的新表单或门禁，不要求员工逐项填表。复用[成本口径](gap06-cost-measurement.md)、[真实需求基线](../reviews/2026-10-15-phase-two-baseline.md)和[最终方案](../reviews/2026-10-16-phase-two-final-plan.md)，本页提供更具体的字段与计算口径，不建立第二需求权威。固定反例见[盘点](2026-10-16-phase-two-counterexamples.md)。

## 来源与可得性

数值分为：实测、由实测计算、估算、未测量/不可得（必须有原因）。另记来源为维护侧核验的产物、用户转交CC回报或自报，不能把转交回报升级为独立实测。来源引用能访问且可重算，才有可核验数字；仅有文字回报则保留回报口径。空值不是0。

| 现有来源 | 实际已有 | 缺少/不能证明 |
|---|---|---|
| project.py质量报告 | tested_at、命令、退出码/状态、部分stdout/stderr、选择和基线 | 单份报告会覆盖；无稳定attempt ID/逐门禁完整起止/费用；tested_at是结束附近时间，不能当开始；日志有截断，不保证原始执行完整 |
| verification/修订/修复/回归/复核记录 | 部分at、tested_revision、状态历史、输入摘要及证据引用 | at常是登记而非执行；没有普遍的实际耗时和人时；同一次结果在多记录引用不等于多次执行 |
| stage_cost.py | ignored scratch可选journal，test/verify/waiting/record_maintenance区间；防并行active、时钟异常；可提供interval来源的usage | 非全任务自动采集；无完整阶段覆盖、provider去重/账单认证；source只是声明。不能因局部journal有值就说总成本完整 |
| 宿主/CLI/CI | 既有个别演练有外层计时、用量和CLI估算费用 | 未在本轮检查任何私有会话或账单；不能承诺所有CC/Codex宿主有相同导出字段；父子调用是否重复需按来源核对 |
| Git | 提交、diff、对象关系和产物版本线索 | commit日期不是开发开始/结束、人类活跃工时或执行时刻；记录提交不等于当时重测 |
| CC转交回报 | 问题、尝试/轮数、部分墙钟和限制 | “运行2小时”、subagent_tokens、额度/context不可直接换算实际人时或金额；缺原件不声称重算过 |

已有测试[test_stage_cost.py](../../tests/test_stage_cost.py)断言局部计时分离、不修改验收、拒绝account/session/context冒充interval和本地忽略要求；没有断言自动采集全宿主、事件去重或收益报告。本轮未执行这些测试。

|---|---|---|---|

| 资源执行时间 | 明确资源/执行单元的区间时长之和，秒；区别于用户等待的墙钟 | 可识别worker/CI job和parent ID | provider父值包含子值时不能再加；没法区分则不汇总资源时间，不冒称CPU时间 |
| 外部等待 | 产品/登录/权限/环境/后端等阻塞区间，秒及原因 | 问题/等待/解阻事件和其他运行区间 | 可与其他工作重叠；不直接从端到端减去全部等待；若给扣等待诊断值，用明确的独占等待区间并集 |
| 人工实际投入 | 人的实际活动时长之和，人时，说明角色与范围 | 已有可信工时或自愿抽样、适用授权 | 消息间隔/数量不等于人时；无记录为未知，抽样外推标估算及范围 |
| 人工介入 | 去重的决策/操作事件数，按必要、不必要、未知分类 | 用户事件引用+目的+结果；补充同一问题不机械多计 | 区分产品权威、资料权限、操作与命令选择/抄记录；分类争议保留未知，不能自动等同Agent失误 |
| 维护与返工 | 重复登记、纠错、失效重建、误阻塞调查、重测/复审的活动分类；次数及可得耗时 | execution/event引用和变更原因，关联被替代尝试 | 作为原运行/人工总量的子分类，不再次加总；次数不能换分钟；修复真缺陷不等同流程浪费 |

| 运行费用 | 可归属CI/设备/计算金额，包含失败尝试 | job/设备租用ID、单位、用量、账单或费率 | 本地执行秒数不自动是金额；共享基础成本单列，未测不填0 |
| 首次准确结项 | 首次完成声明经完整条款复核在约定观察窗内无需因误判撤销；同时报告判定时点 | 首次声明/状态、后续更正、审查及完整条款 | 新产品变更与旧结论误判分开；尚在窗口内标待定；从未完成为未形成首次结项样本，不当成功；未成熟不报最终漏出率 |

| 恢复与覆盖可得性 | 接手开始→正确继续的时间、补充资料/提醒；完成/失败/中止/进行中样本及数据缺失 | 新会话或非原作者演练轨迹+需求批次清单 | 正确停止也记录但不冒充开发完成；不能只报成功样本；缺字段按指标报告n/N和原因 |

## 最小关联字段（候选数据合同，不是新增必填文件）

从现有来源派生：project/feature、source_event或run ID、attempt及parent ID（可得时）、stage/role、事件类型、真实起止和时区、需求/代码/Skill版本、结果、产物引用/摘要、来源、可信级别和缺失原因。现有记录没有的字段不能补造；仅用文件+字段/行号定位的临时键只证明导出条目身份，不证明两个条目不是同一底层执行。

去重优先provider/CI原生事件ID并结合来源账户/会话范围；相同ID只计一次，父子汇总与明细选一种。无原生ID时，用命令、版本、产物与时间判断可能重复，无法确认则不强行合并或相加。失败/重试是真实不同attempt要保留；同一次结果复制到task、fix和verification只算一次执行。

时间默认保留原精度和时区，跨设备仅在时钟可校准时合并；当前monotonic适合单机区间，不跨重启比较。给图表/报表的分类可以重叠，但总量不能靠重叠分类求和。

## 对照与收益计算

首个适用试点建议Android，沿用已有交付点。对照是相同coding agent的现有流程与改进流程，记录需求复杂度、范围、代码/测试基线、人员熟练度、模型/Skill/工具、外部依赖及环境。固定输入隔离演练避免答案泄露、记录顺序及缓存/熟悉效应；真实匹配任务不能冒称随机实验。历史任务为弱对照，纯人工对照另列，不将coding agent收益全部归因Skill。

- 同范围可比任务差额=对照−当前；比例=差额/对照。对照缺失、为0或范围/质量不等价时不算比例。
- 多任务用同一可比集合求总差/总对照，同时展示中位数/范围，不平均不同分母百分比；缺失不同指标分别给有效样本数。
- 已有[Verify同输入对照](2026-10-08-verify-same-input.md)能重算两个合成例的墙钟与CLI估算费用，不证明真实需求平均收益，不能据此取消v6必要复核。
- 建设投入、日常维护、运行和人工分别列；综合成本只有单价/分摊假设充分时才估。建设摊销单列期限/样本，不在多个任务重复全额计入。释放时间不等于现金节省。

## 未来采集/报告的验收反例（未开发、未执行）

| 反例 | 应有结果 |
|---|---|
| 同调用在主代理汇总与子代理明细出现 | 去重或选择单一口径，不能重复计费 |
| 并行两个10分钟审查，时间完全重叠 | 墙钟10分钟；资源时间只在可明确独立时记20分钟，另列 |
| 只有“登记完成时间”、没有测试起点 | 运行耗时未知，不倒推 |
| 用户说“跑了2小时”、没有分段原件 | 报告来源及约2小时经过窗口；人工、净运行、金额未知 |
| 前次complete后发现证据不足而撤销，后又成功 | 最终交付可成立，但首次准确结项失败不能抹去 |
| 累计subagent_tokens多轮回报或账户额度变化 | 不相加充当区间计费用量；无法解析口径就标未知 |
| 一个进行中/失败任务有投入但无交付 | 纳入投入和样本状态；不从成功样本统计里隐去；不为缺失填0 |
| 模型/宿主无账单导出，只有实际usage | 能核对价格才估算，并披露价格/币种/规则；不能将订阅上限写成实付 |

## 输出与当前可作的结论

简报：范围/版本/样本状态 → 时间/人工/费用/维护/质量 → 有无可信对照 → 缺失和限制 → 下一项有据改进。明细字段：指标｜对照｜当前｜差额｜比例｜实测/计算/估算/未知｜来源｜限制。汇报是派生视图，不是新需求权威或结项门槛。

不自动抓取键盘/屏幕、读取私有账单或上传会话；原始业务日志、标识、token不为统计传播。使用已授权、可访问来源，私有原件引用与共享脱敏摘要分离，来源丢失就披露可复核性下降。

当前已完成的是字典和来源能力核对；没有完成采集器、计费验证、真实人时测量、成本对照或净收益证明。本次不重跑业务验收、不开发新采集工具、不改变CC安装及正在运行的任务。
