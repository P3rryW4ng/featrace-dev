# 能力标准、评分与当前基线

核对：2026-10-23。维护侧评估入口，不是安装运行指令、业务验收合同或新增发布门禁。范围先覆盖影响分析、测试选择、验收判断；不重新运行不变测试，不建立逐业务需求永久评分档案。

本页首版基线建立于0.24.0发布前，之后已随该版本发布。表内“未发布工作树/CC0.23.1”描述基线采集时身份；当前正式CC为0.24.0，未因此重新执行评测或改变未知评分。

## 评价的三个维度

每个能力分别显示：①能力在本场景是否达标；②证据来自程序/源码核对、隔离Agent执行还是自然项目；③同范围质量下的执行、维护、审阅、返工与人工成本。程序保护通过不能代替Agent正确理解需求，不能把测试数量换成整体完善百分比。

| 场景得分 | 定义 | 判定要求 |
|---|---|---|
| 0 | 不达标 | 已观察到错误行为，或必要保护被突破；标出具体事实 |
| 1 | 部分达标 | 有实质缺口，尚不足以满足预先约定的标准 |
| 2 | 达标 | 满足本场景预先约定的必要标准，没有以无依据的扩大检查替代判断 |
| — | 未知/未评测 | 缺原始输入、执行、权威或可靠结果；不计零，也不算通过 |

分数属于“指定版本/输入/场景中的能力表现”，不是模块永久得分。严重问题单列：错误结项、越权、隐去真实失败、误删除、泄露。任何其他高分或速度不能抵消；该场景不能宣称达标，须说明处置。评分不依赖固定命令/测试数量；合理不同实现均可达标。有争议的需求或证据先标未知，不能凭评估者偏好扣分。未知数量和未执行场景始终显示；当前不提供模块加权平均、全Skill总分或成熟度百分比。

## 能力合同

### 影响分析

输入是原始需求、实际差异、相关代码/资源/调用方及适用规则。输出是有因果依据的标准、影响范围、无影响理由与局部未知。

| ID | 达标行为 | 不能接受的反例 |
|---|---|---|
| IMP-01 | 声明范围的局部失效；构建输入宽不扩大业务主张 | 合并无关文件/改说明就重验父需求所有逻辑 |
| IMP-02 | 识别真实共享调用、交互、状态和接口影响；未知诚实保留 | 用“UI”标签遗漏点击/焦点变化，或因共享渲染强测全部业务 |
| IMP-03 | 未知只阻塞相关动作，但未解决前不能整体结项 | 局部未知阻塞所有独立工作，或跳过未知直接结项 |

边界：内核不能证明调用方发现完整、分类正确；声明结构通过不是IMP-02的通过证据。

### 测试选择与执行

输入是影响分析、真实测试断言、环境与输入身份、现有执行和实际授权。输出是足够的最小检查集合与合法复用/重跑理由。

| ID | 达标行为 | 不能接受的反例 |
|---|---|---|
| SEL-01 | 必要风险有覆盖；每项强制检查有因果或项目规则依据 | 漏验、拿编译代替视觉、无依据整套重跑 |
| SEL-02 | 复用仍适用且完整的结果；真实相关输入/环境变化使相应结果失效 | 重复登记重跑，或工具链已变仍用旧结果 |
| SEL-03 | 授权调查产生的真实执行可直接用于后续判断 | 调查绕过权限，或成功调查再物理跑一次只为登记 |

边界：现有必需门禁继续满足；测试是否充分取决于真实断言，而非方法名、数量或退出码。

### 验收判断与交付

输入是预期、原始事实/断言、实际对象与时间、相关无影响证明及未解决失败。输出是有范围的支持/部分支持/未知判断与截至此时的交付。

| ID | 达标行为 | 不能接受的反例 |
|---|---|---|
| ACC-01 | 判断证据真的支持预期；区分静态推断、运行观察和未覆盖 | 编译成功即结项，或对无影响主张无依据强制端到端重测 |
| ACC-02 | 独立评审只作用于必要标准，真实出处绑定相关事实 | 一个共享标准强制全任务深审，或无实际独立评审却声称完成 |
| ACC-03 | 真实失败保留；as-of/current时效分别判断 | 静态/过期结果解除运行失败，全部截图统一过期 |

边界：有效期不能证明远端环境未变，宿主出处字段不能证明上下文真的独立。

## 场景集与执行方式

维护[场景与测试映射](../tests/capability-cases.json)：SC-01私有UI、SC-02共享渲染、SC-03键盘交互反例、SC-04接口/状态反例、SC-05复用及未知调查、SC-06失败及当前环境。每项明确必须覆盖、不应强制和允许差异，不规定唯一命令。全部Agent状态为not_run；目前是可执行程序测试引用加Agent场景规格，尚未准备全部原始项目夹具，不能说已完成真实跑分。

程序用例可用标准unittest入口按需执行，例如在tests目录运行 `python3 -m unittest test_hardening.HardeningTests.test_unrelated_branch_commit_does_not_expand_claims -v`。这只是复用入口，不要求为了评分再跑一遍。脚本修改仍遵守AGENTS的完整当前套件要求，使用同一次日志更新映射，不加第二套重复评分测试。

Agent场景执行前补齐最小原始需求/代码/规则及允许的副作用，先固定期望边界；执行者只拿正常请求、实际Skill及必要原始输入，不给评分答案或诱导结论。结果评估对照标准核实实际工具调用和产物。已公开固定场景用于回归，不当作未见测试；另需真正未用于调试的保留场景或自然新需求。当前没有已执行或已保留的盲测样本，不能称泛化能力已证实。未经用户/宿主授权不派Agent、不操作设备或外部系统。

每次结果只保留必要信息：版本/源码/输入身份，场景/能力ID、0/1/2/未知及具体事实，严重问题，证据位置，已知限制、归因和可得成本。同一场景关联多个能力不算多次独立样本。重复运行只报告实际次数，不凑样本；实现和标准同时修改时说明标准为何改变并保留旧事实。

## 持续开发与版本差异

每次维护先指定要改善的能力ID和反例，再改实现；回归只按实际变动与仓库规则执行。用现成产物更新分数，不为了内部阶段重新测试/深审。纯文档调整不触发全套运行。

版本对比使用相同原始输入、质量边界与可比环境；代码、宿主、模型、账号、缓存等差异要注明。分别报测试执行、身份核对、记录维护、审阅、返工、人工等待/操作、重复命令、可得模型/运行费用。未知不填0，人工等待不当工时；相同事实只统计一次，并行时间不相加。报告n/N与未测数，少量场景不宣称整体准确率、节省率或成熟度。

问题归因区分内核、指引、Agent、宿主、项目/环境及评测标准错误，允许多因/未知。维护文档记录当前结论和下一步，原始证据引用既有验证入口；不在业务项目新增评分表、后台调度或永久全文档案。日后只在自然使用或相关修改中补证，不以“模块都要有分数”为理由制造无关测试。
