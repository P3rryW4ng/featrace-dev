# FeatraceDev

**简体中文** | [English](README.en.md)

**Feature · Trace · Delivery** — 将持续变化的需求转化为可验证的交付。

帮助Claude Code、Codex在已有项目中调查影响、开发、修复和验收。以代码、配置、测试和实际产品意图为依据，选择需要验证的范围，保存必要的当前事实，避免局部修改牵连全部业务。

| 对象 | 当前状态 |
|---|---|
| 正式发布版本 | **0.23.1**；当前任务工作流，11运行文件 |
| 验证范围 | 内核150项回归；隔离包与合成规模验证，真实新需求仍待试点 |
| 真实效果 | 第二阶段尚未完成；分类、接续和实际净成本待新需求验证 |

0.23.1替换旧工作流，不兼容旧需求台账。旧工作继续使用固定0.22.0；本包不迁移或删除业务记录。发布/实际安装身份见[维护入口](MAINTAINER.md)。

## 新架构做什么

- 按实际因果影响组合展示、交互、状态、接口、共享和设备检查，不默认重验整个父需求。
- 分开业务影响、产品依据与执行输入；复用有效检查，明确实际观察、静态分析、失败和未知。
- 一份项目策略、一份有上限的活动任务；重要意图/约束回到测试、注释或项目既有精简说明。
- Figma作为设计来源时按目标节点读取，复用项目组件并做局部视觉对比；连接能力由实际宿主提供。
- 自有任务输出按确认的自然日策略清理；查询与长内容分页，不永久保存每个需求全过程。
- 复用真实同范围授权；实际冲突/资料/账号/宿主限制才询问。直接沿用宿主原生任务/计划工具及样式；无工具则正常简短说明进展，不手绘勾选框或固定阶段清单。

这些是0.23.1的能力边界，安装旧0.22.0不会获得新内核。它不能保证发现全部动态依赖、自动判断所有视觉体验或证明宿主独立性；代码与结构正确也不等于符合产品预期。

## 正式版安装与更新

需要Python3.9+、Git和适用宿主；Android还需项目要求的JDK/SDK。正式安装使用固定0.23.1发布分支：

```bash
git clone --branch release/0.23.1 --single-branch https://github.com/P3rryW4ng/featrace-dev.git
cd featrace-dev
python3 scripts/install.py --agent both
```

已有克隆/安装先保留本地改动，核对正式分支与内容。旧release分支上git pull不会升级版本，须显式获取并切换到release/0.23.1。只有在对应正式树上才使用`--update`；单独选择`--agent claude`或`--agent codex`。安装后打开新会话。安装器拒绝覆盖不属于本工具或被本地修改的副本，更新前备份；`--uninstall`移至备份。安装器校验已提交的release.json、本地固定发布引用及运行/安装器内容。开发试装必须显式--development并使用独立身份；本地匹配不等同于远端签名认证。

旧正式版的命令、验收合同和记录用法见[固定0.22.0说明](https://github.com/P3rryW4ng/featrace-dev/blob/54c5260fd6688a0bca9c83f29bad240321a67b52/README.md)，不在当前入口重复。新包不迁移或删除旧.agent-workflow业务资料；明确接续旧记录时使用固定旧版。
