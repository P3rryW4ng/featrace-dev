# Current tasks: implementation, verification and retention

This replaces the feature-ledger workflow. One bounded task, current scoped facts and disposable logs; no world snapshots, schema migration, report mirrors or permanent feature map. Code/config/tests are implementation facts, not proof of product intent. Read only needed sources/callers/resources; unknown/dynamic relationships remain explicit.

## Project setup and policy

Inspect applicable project rules/hooks once, reconcile only real conflicts, reuse current same-scope user grants. `task_workflow.py policy ROOT --json POLICY` publishes one `.featrace-policy.json` and a narrow owned block ignoring `/.featrace/`. This is an authorized project edit, not permission granted by a flag. Tracked local data or custom-block conflicts refuse; existing user ignore content is preserved. Policy may be shared after privacy review; task/log data is local and not automatically committed.

Policy fields:
```
{"policy_contract":1,"authority":"actual scoped decision reference",
 "timezone":"Asia/Shanghai","retention_days":7,"cleanup":"forget",
 "handoff":null,"rules":[]}
```
`cleanup` is manual/compact/forget. Seven days is the normal requested project choice, not a universal retention law. A rule contains `source`, `sha256` (filled from the actual source on policy preparation), `paths` (glob patterns), `operations` (test/build/device/commit/review/configure), `environment` (any/test/local/production), `decision`, `permission` (allowed/denied/ask/not_applicable), and actual `authority`. Empty rules means reviewed absence in this scope, not proof no injected rules exist. Changed applicable sources need reconciliation. Kernel-run build/test/device checks enforce applicable denied/ask decisions; host actions/commits still require the Agent to apply actual rules. A file cannot disable higher-priority instructions or hooks.

## Plan the change

`begin ROOT ID --request "original request"` creates `.featrace/tasks/ID.json`. Use a real product ID if available/required; otherwise a local ID is enough. Activation/status/help do not initialize projects. Do not create a new ID to hide an active failure or omit a relevant unresolved issue.

Investigate scope, then `plan ROOT ID --json PLAN`. Required fields:
- `reason`: actual causal basis; `categories`: relevant presentation/interaction/state/interface/shared/device/configuration combination;
- `scope`: precise affected code/test paths; `exclusions`: other changed path → causal no-impact reason; `constraints`: applicable source path → actual decision; `unknowns`: unresolved effects; use `{reason,criteria:[IDs],checks:[IDs]}` for local unknowns, or a string only for genuinely whole-task unknowns;
- `criteria`: `{id,expected,kind:changed|unaffected,inputs:[precise behavior paths],sources:[optional authoritative source files]}`;
- `checks`: `{id,argv:[executable,args],inputs:[precise execution paths],covers:[criterion IDs],reason,timeout:seconds,environment:{target:"actual target",kind:"local|test|remote|device|production"}}`;
- `review`: `{independent:bool,reason}`; shared effects require independent review; other risks/project rules may too.

**Influence and compiler inputs are distinct.** Checks may include paths beyond semantic scope. Optional `input_sets:[{kind:git_tree|tree|file,path:"relative path"}]` fingerprints current membership/bytes without storing a manifest. `git_tree` includes tracked plus nonignored untracked sources under that path; `tree` also includes ignored files, so do not select output/cache trees accidentally. Avoid compiler outputs as inputs unless intentionally validating them. `external_inputs:[{kind:file|tree,path:"absolute actual toolchain/dependency path"}]` includes declared JDK/SDK/dependency identity. Actual environment-variable values are fingerprinted, never copied into the task. Environment metadata needs a valid kind and actual target; remote/device also declare `policy_environment: local|test|production` so test permission is not inferred from a device label. Production, remote and device results require bounded nonreusable cache settings. `env_keys` adds relevant actual environment keys to common toolchain keys. The helper cannot discover all compiler, native library, device or remote state automatically.

Repository input links are accepted only when declared, relative, existing, internal and pointing to managed target members; outside/dangling/cyclic links refuse. A broad compiler set is conservative execution invalidation, not permission for whole-business review. A directory group avoids persisting thousands of paths but may overinvalidate builds; refine it from actual build knowledge, never omit real inputs to claim cache reuse.

Optional `cache:{mode:content|never,max_age_seconds:N}`. Pure local deterministic checks may reuse matching content. Mutable remote/device environments require `never` plus explicit validity duration (at most 86400 seconds). Such a current result may support an assessment until expiry, but another run physically executes again. Unknown/untracked external state must not be declared hermetic. No universal cross-machine result cache exists.

Bind real PRD/API/decision files in the relevant criterion sources, not compiler inputs merely because they authorize an expectation. Request text and source contents must actually be read; hashes do not prove source interpretation. A source/wording change renews the corresponding assessment, not unrelated claims or unchanged physical executions. Existing raw observations keep their original time/target/fact ID when behavior inputs are unchanged; reassess their actual sufficiency against the new intent, never silently promote them.

After coding, refresh the same scoped plan against actual differences. `scope` declares this task’s owned change paths. Other branch/worktree changes are reported as an advisory count, not silently certified unaffected or included in a whole-branch freshness stamp. Inspect relevant callers and expand scope/checks when there is an actual causal relationship. Exclusions are optional no-impact explanations, not an inventory of every unrelated file. Drift in selected task inputs and changed applicable rules still require scope review. A scoped unknown blocks its associated claims/checks; unresolved unknowns always block closure. Required checks are selected once, deduplicated; don't first run the same check outside the runner.

## Execute and assess

`run ROOT ID --check NAME` executes only the selected command when there is no reusable current success. Use `--investigate` only for a selected, authorized check needed to resolve an unknown: it bypasses the unknown gate, not source freshness, permissions or failure protection. Its execution is marked investigation; it cannot make an unresolved task eligible. Once the unknown is investigated and the plan refreshed, matching successful execution can be assessed without a registration rerun. Failure/timeout/input drift/missing or damaged output never means pass. Output is stored under ignored `.featrace/artifacts/ID/`. Report actual `git_head_at_start` plus input digest; a dirty worktree isn't magically the committed build. The helper is not a command sandbox. Permission matching includes the selected semantic paths, execution files, repository command paths and declared input sets; sets match actual selected members (including members of explicit directory inputs), not merely possible path prefixes, and do not broaden business acceptance. Split/refine checks if this intersects unrelated restricted inputs; do not label an actual command harmless to bypass a rule.

For task-owned screenshots/text/binary evidence, `attach ROOT ID --file exact-source` creates a registered copy under the task artifact folder (at most32 copies, each at most16MiB within the64MiB task budget). Use its returned path as evidence. The original is never deleted. Remove only your own disposable staging copy once verified; do not leave unregistered scratch as a substitute for managed retention.

For facts:
```
observe ROOT ID --criterion C --kind runtime_observation --target "actual installed artifact/device identity" --observed-at ISO_WITH_TIMEZONE --actual "observed result and scope" --evidence exact-relative-file
observe ROOT ID --criterion U --kind static_analysis --observed-at ISO_WITH_TIMEZONE --actual "causal proof of no influence" --evidence exact-relative-file
```
Use `--status failed|unavailable` when appropriate. No observations before task creation, future times or missing actual runtime target. Registration HEAD is not an installed-build identity. Static passed is for unaffected claims; it cannot prove new rendering or replace an actual runtime failure. Relevant earlier failures cannot be removed by editing the plan. An unresolved runtime failure is tracked separately from the latest observation. Unavailable/static registrations cannot clear it or remove its criterion; a later targeted runtime pass must be at least as recent as that failure, and preserves the resolved failure reference. Original failure logs survive until eligible cleanup.

`review-input ROOT ID --criterion C` gives the current exact fact IDs and claim digest. Read `detail ROOT ID --section criterion|facts --criterion C` and exact scoped evidence/code when needed. Then `assess ROOT ID --criterion C --verdict supported|partial|unknown --reason "actual sufficiency"`. This is semantic judgment, not approval merely because a command succeeded. Review each changed/unknown claim and relevant no-impact proof; don't deeply review every unrelated old requirement.

Required independent assessment uses `--independent --provenance PATH`. A genuine host fresh-context return must include task, criterion, criterion_digest, facts, verdict, fresh_context:true, host, context_id, reviewer, reason. The helper checks structure/identity, not whether the host ID is genuine; never manufacture it. Correcting an overbroad evidence demand using the same facts is allowed; runtime failure remains a separate blocker. Don't add whole-history review as a substitute for causal analysis.

## Query, close, clean

`status ROOT ID`, `list ROOT`, `storage ROOT`, `locate ROOT QUERY` (filenames) and `code ROOT LITERAL` (current tracked code matches) are read-only. Follow pagination/exhaustion markers. `detail --section request|plan|receipt|limitations|criterion|facts --offset N --limit N` pages exact selected content; status does not dump a large receipt or limitations. CLI output is capped at16KiB and reports unavailable rather than silently trimming when a larger view is requested. Follow the detail cursor; a preview is not the whole source.

`close ROOT ID [--limitation TEXT...]` requires all scoped criteria/current checks/required reviews, then writes an as-of receipt. No extra test run, full-PRD review or full-history report reread. Complete stays an as-of fact, not current HEAD certification. Persist enduring intent/limits in tests/comments/existing project issue or constraint files, not a second per-task permanent archive.

Project starts and closures opportunistically sweep at most25 task names, rotating a tiny local cursor so active tasks cannot starve later expired tasks. `maintain ROOT [--limit 1..100]` provides an explicit entry for host/team scheduling; no personal cron is installed. Cleanup uses the task's completion-time policy and IANA calendar date, never incomplete tasks. `cleanup ROOT ID` previews; `--apply` compacts and removes only UUID logs with the exact runner-owned header and registered evidence copies whose hashes still match; `--forget` removes the task too. A surviving `--handoff PATH` must contain every limitation before forgetting. Unknown files/links and incomplete handoff retain data; investigate instead of deleting it. Automatic cleanup failures are retained, counted and visible in maintenance results. External screenshots/originals/code/old ledgers/Git history are never deleted.

Limits:256KiB task,512 exact paths/list,250000 transient execution entries/32GiB bytes,16MiB hard log cap,64MiB task-log budget,64 POSIX task lock slots plus a separate maintenance lock. The runner never writes beyond its selected log budget; other tools/caches and external evidence are outside this quota. Record overflow refuses rather than silently forgetting facts. Reading current facts is bounded; semantic dependency completeness, host independence and natural-project gains remain empirically testable limits, not mathematical guarantees. This package supports POSIX execution, not an untested Windows runner.

`storage` is a read-only local inventory: overall regular-file bytes (bounded to100000 entries, explicitly partial beyond this), link count, task count and paged task state/record sizes. Stale incomplete and unreadable records are warnings; `counts_scope: selected_page` means state/age counts cover only that page. Follow pagination. Last recorded activity is not measured human effort. Unknown local files count toward bytes, external build caches/originals do not. No automatic abandonment/deletion or project-wide total size guarantee is introduced.
