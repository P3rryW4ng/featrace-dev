# Commit final delivery records locally

Load only after Deliver has registered the applicable baseline, set the feature to `complete`, and passed the final read-only check. This is the default authorized local bookkeeping continuation, not another acceptance gate. An explicit no-commit request, repository policy, unavailable Git identity or inseparable unrelated edits takes precedence. Never archive, push, open a PR or re-run quality gates merely to make this commit.

1. Read current Git status and the complete unstaged/staged diff. Identify only shareable paths under `.agent-workflow/features/<ID>/` that the current delivery changed. Include the reviewed report and canonical records with their generated views as applicable. Exclude ignored original sources, raw quality reports, scratch, `acceptance/`, other features, business code and unrelated staged files. Follow `git-sharing.md` and the project's own rules.
2. If the index has unrelated content or a delivery file contains inseparable pre-existing changes, leave everything untouched and report the exact obstacle. Never use `git add -A`, reset, stash or fabricate a clean tree. Otherwise stage only exact feature paths or reviewed hunks, inspect `git diff --cached --stat`, follow [output-privacy.md](output-privacy.md) for only these staged new record lines before displaying/importing them, then inspect the complete reviewed diff and run `git diff --cached --check`. Batch explicit paths; a privacy finding pauses this commit, not unrelated testing. Do not dump private originals, scan all historical sources or install hooks.
3. Commit only after the staged content matches the completed delivery, using the project's convention and a subject such as `docs(OGFR-7840): record verified delivery`. Report the commit hash and any intentionally local-only evidence. If nothing shareable changed, report that no final commit was needed. A workflow-only commit must not be represented as a new test run or installed build; existing audit rules determine whether evidence remains current after it.

Task-level implementation commits remain governed by `task-commit.md`. This final records commit follows them; it never replaces them. Keep `complete` when a safe Git commit cannot be isolated, and state that local publication is pending rather than reclassifying accepted behavior.
