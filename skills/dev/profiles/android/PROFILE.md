# Android adapter

Require Android plugin evidence (`com.android.application`, `com.android.library` or an explicit version-catalog plugin mapping); Gradle alone is not Android. Read module setup, Compose/XML, navigation, DI, networking, persistence and tests from actual code.

`scan-project.sh <PROJECT>` is the legacy keyword scanner retained for compatibility/reference, not the normal entry. It overwrites baseline files, so do not run it over a reviewed baseline. Use shared `core/scripts/project.py scan-prepare`, inspect and edit the printed draft, then `scan-publish`; see `../../core/references/project-baseline.md` for retention and recovery. The shared scan also parses common static Gradle `include`, `projectDir` and `project(...)` dependency forms into `modules/candidates.json` and `.md`. Review each candidate and every parsing gap against the actual Gradle setup; dynamic configuration and convention plugins are not resolved, and candidates never become catalog facts automatically.

`run-quality-gates.sh <PROJECT>` is the legacy `./gradlew check` helper. It does not necessarily compile every target or run device tests. The normal quality entry is `project.py check` with explicit commands in baseline/quality-gates.json. Select real module/variant tasks from project CI/Gradle; record whether emulator/device and SDK are available. Do not equate gradle check with full Android verification.

For Android device acceptance, follow `../../core/references/verification-workflow.md` before handing setup steps to the user. On a named, authorized test emulator or device, prefer existing ADB/project instrumentation/UI automation to prepare reversible language, night-mode, orientation or display settings and capture objective observations. Read the previous setting, verify the effective system **and app** state after switching (per-app language/theme may differ), and restore/verify the previous value afterward. Record the installed APK identity separately from the setting and actual screen assertion. OEM restrictions, unavailable ADB/credentials and subjective appearance are explicit remaining gaps, not reasons to claim a pass from a successful shell command. This adapter supplies a routing rule, not a new device driver or universal command recipe.
