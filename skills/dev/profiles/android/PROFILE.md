# Android execution adapter

Use only when actual Android plugin evidence exists; Gradle alone is insufficient. Inspect the affected modules, convention plugins, variant/build configuration, Compose/XML resources and relevant callers. Do not generate a permanent whole-project module dossier. Use current Git/rg/Gradle knowledge; dynamic build logic remains unknown until inspected.

Select real existing tasks from project CI/Gradle. For an isolated UI change, test its rendering/layout/affected states and necessary build, not every business condition on the page. Keyboard/insets changes need focused scrolling/focus/device evidence. Shared components expand affected render callers. No fixed mandatory suite or device matrix is added by this adapter; actual project mandatory checks remain applicable.

A check's semantic criteria can mention two UI files while its execution `input_sets` include app sources/resources, dependent modules, build-logic, Gradle scripts/catalog/wrapper and proto/lock files actually used. The kernel fingerprints selected directory membership and bytes transiently. Include ignored source inputs via `tree` or explicit file when needed; omit generated outputs/cache directories. Using a whole-repository git_tree is a safe conservative input selection, not proof all external inputs are covered or reason to reaccept the entire PRD.

Declare the actual JDK/tool executables and relevant SDK/dependency inputs as `external_inputs` (resolved file/tree), actual JAVA_HOME/ANDROID_SDK_ROOT/Gradle environment via `env_keys`, and relevant versions/device/emulator identity in environment metadata. For Gradle, wrapper/config bytes do not identify downloaded JDK, AGP/dependency JARs or changing services. Either fingerprint the relevant immutable dependency/toolchain files, use an actually hermetic locked environment, or disable reuse and describe the unknown. Do not mark a check cache-safe merely because its argv is unchanged. Use `environment.kind=device|remote` plus the actual `policy_environment=test|production|local`; neither field grants permission. Emulator/device/remote checks use `cache.mode=never` with a bounded `max_age_seconds`; there is no cross-machine device cache.

Run through `task_workflow.py run`, once, so actual start HEAD, content input digest, exit status and output identity are captured. Correct a failed test, replan changed inputs, rerun only its necessary check. Do not run a direct diagnostic success and then repeat the same command just to register it. Source/test edits don't automatically stale unrelated module records because there are no mandatory module records.

For an authorized emulator/test device, use existing ADB/project instrumentation to prepare objective states, including recoverable settings when the actual host permits them. Save/restore and verify changed settings, account/environment and installed APK hash separately. Reuse standing test authorization; user input is needed only for actual credentials, consent, inaccessible actions or a true permission boundary. No new general device driver is bundled. Do not claim an S21 result certifies an untested A55; do not infer actual visual correctness from test structure or a successful shell command.
